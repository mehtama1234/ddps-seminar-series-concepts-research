Talk 114 · UC Berkeley

Aditi Krishnapriyan: Bridging Numerical Methods and Deep Learning with Physics-Constrained Differentiable Solvers

This whole series is about getting computers to predict how physical things behave by having programs learn from examples instead of only hand-written math. This talk shows one way to do it: take a numerical method (a step-by-step recipe that engineers use to predict PDEs—rules describing how things like heat, air, or water change from place to place and moment to moment) and make it so gradients (the nudges you use to tune a learning program's dials) can flow backward through it. That way, a neural network can learn to solve these equations while staying true to the physics.

YouTube source · Talk page

Core Problem

Programs that learn from examples (neural networks) are good at spotting patterns in data, but they can completely ignore the physics rules you care about. Old step-by-step math methods (classical numerical solvers) stick to the physics but cannot learn new tricks from data. The challenge: build something that does both—learns from examples AND respects the physics laws.

First-Principles Model

A differentiable solver takes a numerical method (a concrete recipe: set up a grid, compute at each grid point, step forward in time or space) and wraps it so that gradients can travel backward through each step. Instead of solving the physics rule separately and then training the network, you bake the solving process directly into the learning graph. The talk covers three flavors: spectral methods (representing the solution as sums of waves or other basis shapes the network learns to favor), finite-difference (computing changes on a grid), and optimization-based (finding the best answer that satisfies the physics constraint). The network learns which parts of the solver to adjust so predictions match real data.

Key Claims

  • Programs that learn from examples are becoming necessary for predicting systems that change across space and time.
  • Learning from small amounts of data requires keeping predictions physically valid, not just statistically close to examples.
  • You can retrain spectral methods by having the network learn which basis functions (like sine waves) work best for the problem at hand.
  • You can build training that runs the simulator step-by-step inside the learning loop, not just once at the start.
  • Combining classical numerical methods and neural networks as a single trainable system works and solves real problems.
  • Finding learning strategies that work across many different physical systems and network designs is an open goal.

Worked Example

Illustrative: Poisson equation (∇²u = f) on unit square, Dirichlet boundary conditions. Classical solver (FEM, N=10,000 DOFs) solves in 0.1 seconds, condition number ~10³. Differentiable solver trains iterative refinement network to optimize Ax=b solve quality: inputs are residual r_k = b - Ax_k, outputs correction Δx_k predicted by neural network. After 5 iterations: ||x_net - x_exact||₂ ≈ 10⁻⁶ (solver quality). This network becomes a 'learned preconditioner': when embedded in optimization loop for inverse problem (recover coefficients from noisy measurements), the full bilevel optimization (minimize ||Au(θ)-y_meas|| + regularization) converges 3x faster than classical MINRES preconditioner.

Convection-diffusion (advection-dominated, Pe=100): classical solver (SUPG stabilization) requires fine mesh (10,000 cells). Differentiable network learns to stabilize: predicts optimal artificial diffusion coefficient adaptively per element. Learned model trains on 5 solutions, generalizes to 20 test cases with same error as hand-tuned SUPG.

One Level Deeper

Differentiable solver framework: a neural network φ_θ learns to improve an iterative scheme. Classical: x_{k+1} = x_k + M⁻¹(b - Ax_k), M is preconditioner. Differentiable: Δx_k = φ_θ(r_k, A, x_k) learned by minimizing ||x_θ - x*|| over training solutions. Bilevel optimization: outer loop optimizes PDE parameters θ_pde to match data; inner loop solves Ax=b via differentiable solver. Gradients flow: ∂loss/∂θ_pde = (∂loss/∂x) · (∂x/∂θ_pde), where ∂x/∂θ_pde computed via implicit differentiation through solver iterations. Architecture: few-layer MLP takes residual r, previous iterate x, sparse matrix A (via sparse matrix multiplication), outputs correction. This is equivalent to learning the iteration matrix in preconditioned Krylov methods.

Failure Boundary

Learned preconditioner is problem-specific: trained on Poisson, fails on Helmholtz (different spectrum). Transfer learning tricky—matrix shape must stay constant. Ill-conditioned problems: solver learns to accumulate rounding errors (preconditioner amplifies high-frequency noise). Black-box differentiability costly: auto-diff through sparse matrix operations is expensive; explicit differentiation needed. Non-convergence guarantee: unlike classical methods with proven convergence rates, learned solver may diverge on new problems. Memory overhead: differentiable solver stores intermediate states for backprop, requiring 5-10x memory vs. non-differentiated solver. Generalization across matrix sizes: network trained on 100×100 linear systems fails on 1000×1000—no resolution independence. Chaotic behavior: small perturbations in input can cause large changes in learned correction (gradient-unstable), different from robust classical solvers.

Important Terms

Differentiable Solver

A step-by-step numerical recipe whose calculations produce gradients (the directions to nudge), so it can be trained as part of a learning program.

Physics-Constrained Learning

Training a program to learn patterns from data while making sure it obeys physical laws—not by adding a penalty for breaking them, but by baking the laws directly into how the program works.

PDE-Constrained Optimization

Finding the best answer to a problem where every candidate answer must satisfy a rule describing how things change (a differential equation), not just match the data.

Simulation-in-the-Loop

A training method where the program runs the physics simulator step-by-step during learning, not just once afterward, so gradients flow through every step.

Spectral Method

A numerical recipe that writes the answer as a sum of basis functions (common choices are sine and cosine waves, or polynomials), rather than storing values on a grid.

Connections Across The Series

  • This work ties together neural networks that solve PDEs, methods that add physics to learning (called PINNs), programs you can compute gradients through, and classical numerical recipes that engineers built decades ago.
  • It goes further than just penalizing violations of physics; instead, it embeds the solver's structure—the actual computational recipe—into the learning network.
  • It also connects to inverse design (figuring out what input produces a desired output) and control systems, because you can compute gradients backward through the entire solver to tune inputs and outputs.

Practical Caution

A differentiable solver is only as good as the underlying numerical method. If the method is shaky (errors grow when you push it) or misses some detail (approximation error from chopping continuous space into discrete pieces), wrapping it in gradients does not fix that. Making it trainable does not make the physics correct by automatic.

Takeaway

The core idea is that the structure of the solver—how you actually compute the solution—can become part of the network architecture itself, not just a penalty term in a score function. This way, learning respects the physics built-in, while still tuning to fit data.
