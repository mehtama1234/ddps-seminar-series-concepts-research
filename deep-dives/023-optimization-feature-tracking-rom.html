Talk 23 · University of Notre Dame

Matthew Zahr: Model Reduction Of PDEs Via Optimization-Based Feature Tracking

This whole series is about getting computers to predict physical behavior by learning from examples. Some hard problems have sudden jumps—shocks in explosions or flow around objects—that move around as time goes on. This talk is about a trick: instead of trying to compress a fixed grid that watches shocks zoom past, warp the grid so the shocks sit still in a new coordinate system, then compress that simpler view. The method writes this as an optimization problem—find both the physical solution and the grid deformation that work together.

YouTube source · Talk page

Core Problem

When a physical rule (a PDE—a rule that says how something changes from moment to moment or place to place) has shocks or sharp jumps, model reduction is hard. Model reduction means taking all the data from a full simulation and boiling it down to a smaller, faster program that still predicts well. Normally you keep the same grid (the points in space where you measure) and try to compress the results. But when shocks move around, you need a huge number of different 'modes' (different ways to wiggle the solution) to capture them all, and the reduced model either gets fat and slow or smears out the sharp features into blurry wiggles instead.

First-Principles Model

Instead of watching shocks zip past a fixed grid, this method warps the grid itself so the shocks line up. Think of it like moving your camera so a fast-moving object stays in the same spot on screen. The method writes down an optimization problem: find values for both the physical solution and for how to deform the grid, such that everything stays consistent with the physics. When you compress this setup, you reduce not just the numbers describing the solution, but also the numbers describing how the grid bends.

Key Claims

  • Shock tracking can be written as an optimization problem—you solve for both the solution and the grid deformation simultaneously.
  • High-order methods (advanced techniques for numerical solving) keep their nice properties like accuracy and conservation of physical quantities even when you write shock tracking as an optimization constraint.
  • Warping the domain lines up sudden jumps across different time steps, so fewer modes are needed to capture the motion.
  • The reduced model optimizes both the compressed solution and the compressed mesh deformation.
  • The grid warping must preserve the domain edges so interior point movement does not damage the physical boundary.
  • Feature tracking keeps simple compression tools like SVD (a standard matrix trick for data reduction) useful on hard problems where shocks move.

Important Terms

Feature Tracking

Warping the grid in space so sharp features like shocks stay in the same spot as time goes on, instead of moving around.

Implicit Shock Tracking

A method where you write an optimization problem to find the shocks by solving the physics and grid together, rather than manually drawing the shock front.

Domain Deformation

Bending the computational domain (the region in space you are simulating) to line up moving features.

Reduced Mesh Coordinates

A small set of numbers that control how the grid bends when you are working with a compressed model.

Boundary-Preserving Map

A grid transformation that moves interior points around while keeping the edges of your domain fixed and valid.

Connections Across The Series

  • This talk is the optimization-based cousin of registration-based reduced models: both reduce the problem by lining up moving features.
  • It ties to entropy-stable schemes because handling shocks is not just about learning, but also about how you discretize (break space into steps) and how you move the geometry.
  • It also connects to nonlinear reduced models on curved subspaces because grid deformation creates a nonlinear representation, yet keeps simple linear tools like SVD still working.

Practical Caution

Tracking features is not free. The optimization itself costs computing time, and bending the grid can cause real problems. If you bend the grid badly, you might keep the model small but break the edge boundaries of your domain, lose conserved quantities (like total mass or energy), or make the solver unstable and unreliable.

Takeaway

The main idea is that for shocks and sudden jumps, you can first let your coordinate grid flow with the physics before compressing. Moving the grid is itself an optimization problem you solve alongside finding the solution.
