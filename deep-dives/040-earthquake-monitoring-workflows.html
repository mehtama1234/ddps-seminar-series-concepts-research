Talk 40 · Stanford University

Greg Beroza: Towards Complete Machine-Learning-Based Earthquake Monitoring Workflows

This whole series is about teaching computers to predict how physical things behave by learning from examples instead of only hand-written math. One place this matters is earthquake monitoring: seismic sensors record ground shaking, and a computer needs to turn those wiggly recordings into a list of earthquakes (when each happened, where, how big). This talk shows how machine learning—a program with millions of dials it tunes by trial and error until its answers look right—can handle each step of this job better than older methods. But here's the catch: the whole system only works if training data, realistic variations on that data, model design choices, and final checking of the earthquake list all work together.

YouTube source · Talk page

Core Problem

Earthquake monitoring is not one prediction question, it is many chained together. A seismic network runs continuously, recording every ground wiggle. A real monitoring system has to clean up those signals, spot the moment each seismic wave arrives, group wave arrivals from many sensors so they are recognized as coming from the same earthquake, pinpoint where that earthquake happened, estimate how big it was, and keep accurate records over time. If you swap in a learning program to handle just one of these steps, errors pile up: a mistake in spotting wave arrivals breaks the grouping, which ruins the location, which ruins the final catalog. You cannot ignore this chain.

First-Principles Model

A monitoring workflow takes raw seismic recordings and turns them into a structured earthquake catalog. The information shape-shifts at each step: raw signals become wave arrivals (the moment each seismic wave type lands at a sensor), wave arrivals become events (a group of arrivals from one earthquake), events become locations and details about the earthquake. Machine learning shines when it learns these transformations by studying labeled seismic data and artificially created variations on that data that look realistic. But the output that matters is the earthquake catalog, the list geophysicists will actually use. So the right way to score how good a model is should measure the whole workflow, not just how well a single piece works in isolation.

Key Claims

  • Standard earthquake monitoring works as a chain: clean up signals, find wave arrivals, group those arrivals into earthquakes, calculate earthquake locations, and estimate earthquake sizes.
  • Deep learning (a program with millions of adjustable dials tuned by trial and error) can handle individual steps and often finds many more earthquakes than older methods did.
  • High-quality training labels, the shapes and sizes of the learning program, and creating realistic variations on training data are not small details; they decide whether the model works on real seismic networks it has never seen.
  • Replacing one piece of the workflow at a time is simplest to put into real systems because each step can be upgraded alone.
  • Building one learning program that handles several monitoring tasks together, instead of several separate programs, can work better because different seismic tasks share information.
  • Better earthquake catalogs reveal small and previously missed earthquakes that show patterns and tell us where earthquake hazards are located.

Worked Example

PhaseNet, a deep convolutional neural network, picks P-wave and S-wave arrival times on seismic waveforms with accuracy within a few hundredths of a second (±0.2 seconds for P-waves, ±0.2 seconds for S-waves). Compared to expert human picks (ground truth), the distribution is narrow and centered near zero, whereas classical automatic pickers (AR picker) show larger tails and bias. On the Ridgecrest, California aftershock sequence (300 seconds of data), the deep learning catalog finds 10× more events than the standard USGS catalog and 50% more than prior machine-learning catalogs, all from the same instrumental data but with more careful signal processing.

Using the deep catalog for earthquake sequence analysis reveals a spatial-temporal diffusive pattern consistent with fluid pressure diffusion in induced seismicity (Guy Greenbrier fault, Arkansas). Fitting parabolic arc-shaped structures in space-time gives diffusivity estimates of 10–100 m²/s, explaining the temporal evolution of seismicity as fluid propagates through a fault zone.

One Level Deeper

PhaseNet uses a CNN encoder-decoder with three input components (3D velocity). The encoder extracts features from raw waveforms; the decoder predicts P-wave and S-wave arrival times by reconstructing truncated Gaussian distributions centered on phase onsets. The loss trains the classifier to assign high probability at the true arrival time and low probability elsewhere. For the Gaussian mixture model (GMM) association step, each phase measurement is treated as a distribution with mean at the picked time and variance reflecting uncertainty. Soft clustering iteratively assigns phases to events by maximizing the likelihood of a fixed number of events, iterating until convergence.

The workflow is embarrassingly parallel: phase picking and association on different time windows run independently. HypoDD performs precise relative locations using waveform cross-correlation and double-differences, providing sub-meter precision for nearby events.

Failure Boundary

PhaseNet struggles with heavily clipped waveforms (telemetry saturation) or extremely noisy background (e.g., during volcanic eruptions). In swarms where waveforms overlap significantly, picking individual onsets becomes ambiguous; the model must infer which energy belongs to which event. Manual catalog errors (misidentified phases, mislabeled onset times) in training data propagate as a ceiling on accuracy. Out-of-distribution shifts—e.g., teleseismic waves, unusual velocity structures—can degrade phase picks. The GMM association assumes a Poisson process for event times, which breaks down for foreshock-aftershock clustering. Long-term deployment requires retraining on new station networks and instrument types.

Important Terms

Earthquake Catalog

A complete list of earthquakes that were detected, showing when each happened, where, how big it was, and other measured properties.

Phase Picking

Finding the exact moment when each type of seismic wave (the main types are called P and S waves) lands at a sensor in the ground-motion recordings.

Event-Phase Association

Grouping wave arrivals that many sensors recorded so they are recognized as coming from one earthquake instead of separate events.

Data Augmentation

Creating new training examples by modifying known seismic recordings in realistic ways so a learning program sees what stays the same even when conditions change, instead of memorizing one specific setup.

Multi-Task Monitoring

A learning program design where several related monitoring tasks are learned together in one program instead of as separate independent programs.

Connections Across The Series

  • This talk builds on earlier lectures about using physics to guide learning and about surrogate models (programs that imitate expensive calculations): a learned system must fit into the actual workflow scientists use, not stand alone.
  • It connects to active learning and smart ways to collect data because training labels and realistic data variations are essential for machine learning in science.
  • It connects to understanding what we do not know and to inverse problems (figuring out what caused something we measured): how good the earthquake catalog is determines what conclusions downstream about earthquakes and hazards can be trusted.

Practical Caution

Do not judge a monitoring model only by how well it spots wave arrivals at sensors. A model can score high at detecting waves but still produce a bad earthquake catalog if it fails at grouping arrivals into events, locating them accurately, estimating magnitudes correctly, or working on a seismic network it has never been tested on before.

Takeaway

Machine learning for earthquake monitoring should be judged as a complete measurement system, the way you would judge a thermometer or a scale. The output is not a score or a percentage; it is an earthquake catalog that scientists and hazard forecasters will base decisions on.
