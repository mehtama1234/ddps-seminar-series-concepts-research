Talk 40 · Stanford University

Greg Beroza: Towards Complete Machine-Learning-Based Earthquake Monitoring Workflows

This lecture frames earthquake monitoring as an end-to-end scientific workflow where machine learning can improve detection, association, location, and characterization, but only when labels, augmentation, architecture, and catalog validation are treated as part of the system.

YouTube source · Talk page

Core Problem

Earthquake monitoring is not one prediction task. A seismic network produces continuous noisy ground-motion streams, and the operational system must clean traces, detect phases, associate phases into events, locate earthquakes, estimate magnitudes, and maintain catalogs over time. Replacing one step with a neural network helps, but workflow-level errors can still propagate.

First-Principles Model

A monitoring workflow converts raw waveforms into a structured earthquake catalog. Each step changes the information representation: signal to phase picks, phase picks to events, events to locations and source properties. Machine learning is useful when it learns these transformations from labeled seismic examples and augmented data, but the final scientific object is the catalog, so the correct unit of evaluation is workflow quality, not just neural-network accuracy on an isolated subtask.

Key Claims

  • Standard earthquake monitoring is a sequence of pre-processing, phase detection, event-phase association, location, and characterization.
  • Deep learning can replace individual steps and sometimes produces much more complete catalogs than traditional approaches.
  • Accurate labels, model architecture, and data augmentation are not implementation details; they determine whether the model generalizes to real seismic networks.
  • A modular strategy is easiest to deploy because it replaces workflow components one by one.
  • There are advantages to combining multiple monitoring steps in multi-task models because seismic tasks share information.
  • Better catalogs matter scientifically because small and previously missed earthquakes reveal earthquake occurrence patterns and hazard structure.

Important Terms

Earthquake Catalog

A structured record of detected seismic events, including occurrence time, location, magnitude, and related event properties.

Phase Picking

Identifying arrival times of seismic wave phases, such as P and S waves, in continuous waveform data.

Event-Phase Association

Grouping phase arrivals across sensors into a coherent earthquake event.

Data Augmentation

Constructing varied training examples from known seismic signals so a model learns invariances rather than memorizing one network condition.

Multi-Task Monitoring

A modeling approach where related monitoring subtasks are learned jointly instead of as isolated modules.

Connections Across The Series

  • This talk is a workflow-level counterpart to earlier PINN and surrogate-model lectures: the learned model must fit inside a scientific pipeline.
  • It connects to active learning and data engineering because labels and augmentation are central to successful scientific ML.
  • It also connects to uncertainty and inverse problems: catalog quality determines what downstream geophysical inference can be trusted.

Practical Caution

Do not judge a monitoring model only by phase-picking scores. A model can have good local detection metrics and still create bad catalogs if association, location, magnitude estimation, or domain transfer fails.

Takeaway

The first-principles lesson is that scientific ML for monitoring should be evaluated as a complete measurement system. The output is not a classifier score; it is a catalog that scientists and hazard models will use.
