Talk 40 · Stanford University

Greg Beroza: Towards Complete Machine-Learning-Based Earthquake Monitoring Workflows

This lecture shows earthquake monitoring as an end-to-end workflow where machine learning can improve how we detect waves, group them into earthquakes, locate where they happened, and measure their size—but only when we treat training data, data variants, model design, and catalog checking as interconnected pieces of the system.

YouTube source · Talk page

Core Problem

Earthquake monitoring is not one single prediction task. A seismic network constantly records ground motion, and a real monitoring system must clean up the signals, spot wave arrivals, group arrivals into events, pinpoint earthquake locations, estimate sizes, and keep records accurate over time. Swapping out one step with a neural network helps, but errors in one stage can still contaminate the whole catalog.

First-Principles Model

A monitoring workflow turns raw seismic recordings into a structured earthquake catalog. At each step, the information changes shape: raw signals become phase picks (identified wave arrivals), phase picks become events, events become locations and source details. Machine learning shines when it learns these transformations from labeled seismic data and artificially varied examples, but the final product is the catalog, so the right way to measure success is how good the entire workflow is, not just how well the neural network performs on one isolated piece.

Key Claims

  • Standard earthquake monitoring is a pipeline of signal cleaning, wave-phase detection, grouping phases into events, location calculation, and size estimation.
  • Deep learning can replace individual steps and sometimes creates much more complete earthquake records than methods used before machine learning.
  • High-quality training labels, model architecture choices, and creating realistic data variants are not minor details; they decide whether the model works on real seismic networks it has never seen.
  • Replacing one workflow piece at a time is easiest to put into practice because each step can be upgraded separately.
  • Combining several monitoring tasks in a single model that learns them together can work better because different seismic tasks share information.
  • Better earthquake catalogs matter because they reveal small and previously missed earthquakes that show earthquake patterns and where hazards are located.

Important Terms

Earthquake Catalog

A complete list of detected seismic events, recording when and where each happened, how big it was, and other properties of the earthquake.

Phase Picking

Identifying the exact times when different seismic wave types (such as P and S waves) arrive at recording stations in continuous ground-motion data.

Event-Phase Association

Grouping wave arrivals recorded at many sensors so they are recognized as coming from one earthquake.

Data Augmentation

Creating varied training examples from known seismic signals so a model learns what stays the same across different network conditions instead of memorizing one specific setup.

Multi-Task Monitoring

A model design where several related monitoring tasks are learned together instead of as separate independent modules.

Connections Across The Series

  • This talk builds on earlier lectures on physics-informed models and surrogate models: a learned system must fit into a scientific workflow, not stand alone.
  • It connects to methods for active learning and smart data collection because training labels and realistic data variants are essential to good scientific machine learning.
  • It also connects to uncertainty and inverse problems: how good the earthquake catalog is determines what downstream geophysical conclusions can be trusted.

Practical Caution

Do not judge a monitoring model only by how well it picks wave phases. A model can score well at spotting phases but still produce a bad catalog if it fails at grouping arrivals into events, locating them, estimating magnitudes, or working on a new seismic network.

Takeaway

The first-principles lesson is that machine learning for earthquake monitoring should be judged as a complete measurement system. What comes out is not a classification score; it is a catalog that geophysicists and hazard models will actually use.
