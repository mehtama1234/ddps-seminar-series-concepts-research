Talk 83 · Federal University of Rio de Janeiro

Alvaro Coutinho: Enhancing Data-Driven Workflows For Complex Simulations

This lecture shows that data-driven workflows for large simulations must handle I/O bottlenecks by analyzing, reducing, and updating data while simulations run.

YouTube source · Talk page

Core Problem

Complex PDE simulations produce high-dimensional state vectors on fine meshes. Modern computers can generate data faster than disk storage and I/O systems can write it. If workflows wait until after simulation to save and analyze everything, the data bottleneck—the slow speed of moving information between computer memory and disk—becomes the limiting factor in the science.

First-Principles Model

A simulation workflow is a coupled computation-and-data pipeline. Data-driven methods such as model discovery, reduced-order models (simpler stand-in models that capture the essential behavior), physics-informed neural networks (ML models trained to respect physics equations), and control all need snapshots from the simulation. But large simulations cannot always save every snapshot. The solution is to analyze data while the simulation runs and reduce data before writing it to disk: update models during runtime, reduce data before writing, steer simulations based on intermediate results, and combine simulation workflows with machine-learning workflows.

Key Claims

  • Data-driven methods are widely used in engineering and scientific simulations.
  • Large transient nonlinear PDE simulations produce high-dimensional data that stress storage systems.
  • The gap between computation speed and I/O speed makes it hard to save large data to disk for later analysis.
  • Data should be analyzed while the simulation is running or reduced before being saved.
  • Algorithms running during simulation can update data-driven models as new snapshots arrive.
  • In situ tools can merge simulation workflows and machine-learning workflows.

Important Terms

In Situ Analysis

Analyzing data while a simulation is running, rather than after writing all output to disk.

I/O Bottleneck

A slowdown caused by the speed at which data can be read from and written to disk, relative to how fast the computation produces data.

On-The-Fly Algorithm

An algorithm that updates during simulation as new data arrive, without waiting for the simulation to finish.

Data Reduction

Compressing or summarizing simulation data to use less storage and require less time to analyze.

Simulation Steering

Changing simulation behavior or analysis choices during runtime based on intermediate results.

Connections Across The Series

  • This talk complements large-scale simulation and machine-learning talks by focusing on how to move data efficiently through the workflow, not just how to build better models.
  • It connects to reduced-order models because reduction can happen during simulation to avoid saving full state vectors.
  • It also links to real-world machine-learning deployment: whether methods work depends on whether you can actually get data to them.

Practical Caution

If a workflow cannot move data efficiently, a better model will not fix the bottleneck. Scientific ML pipelines must be designed around compute, storage, and I/O constraints.

Takeaway

Data-driven simulation is also systems engineering. The model cannot learn from data the workflow cannot afford to move.
