Talk 83 · Federal University of Rio de Janeiro

Alvaro Coutinho: Enhancing Data-Driven Workflows For Complex Simulations

This lecture argues that data-driven workflows for large simulations must address I/O bottlenecks by analyzing, reducing, and updating data while simulations run.

YouTube source · Talk page

Core Problem

Complex PDE simulations produce high-dimensional state vectors on fine meshes. Modern compute can generate data faster than storage and I/O systems can write it to disk. If workflows wait until after simulation to save and analyze everything, the data bottleneck can dominate the science.

First-Principles Model

A simulation workflow is a coupled computation-and-data pipeline. Data-driven methods such as model discovery, MOR, PINNs, and control need snapshots, but large simulations cannot always export all snapshots. The solution is in situ and on-the-fly analysis: update models during runtime, reduce data before writing, steer simulations, and merge simulation workflows with ML workflows.

Key Claims

  • Data-driven methods are increasingly used in engineering and scientific simulations.
  • Large transient nonlinear PDE simulations produce high-dimensional data that stress storage systems.
  • The disparity between compute speed and I/O speed makes it hard to dump large data to disk for later analysis.
  • Data should be analyzed while the simulation is running or reduced before being saved.
  • On-the-fly algorithms can update data-driven models as new snapshots arrive.
  • In situ tools can merge simulation workflows and machine-learning workflows.

Important Terms

In Situ Analysis

Analyzing data while a simulation is running rather than after writing all output to disk.

I/O Bottleneck

A performance limit caused by slow data reading and writing relative to computation.

On-The-Fly Algorithm

An algorithm that updates during simulation as new data become available.

Data Reduction

Compressing or summarizing simulation data to reduce storage and analysis cost.

Simulation Steering

Changing simulation behavior or analysis choices during runtime based on intermediate results.

Connections Across The Series

  • This talk complements all large-scale simulation ML talks by focusing on workflow infrastructure rather than only model architecture.
  • It connects to ROMs because reduction can happen during simulation to avoid writing full fields.
  • It also links to industrial SciML deployment: data logistics are part of whether methods work.

Practical Caution

If a workflow cannot move data efficiently, a better model will not fix the bottleneck. Scientific ML pipelines must be designed around compute, storage, and I/O constraints.

Takeaway

The first-principles lesson is that data-driven simulation is also systems engineering. The model cannot learn from data the workflow cannot afford to move.
