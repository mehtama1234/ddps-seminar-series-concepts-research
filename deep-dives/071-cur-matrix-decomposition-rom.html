Talk 71 · University of Pittsburgh

Hassan Babaee: CUR Matrix Decomposition For Scalable Reduced-Order Modeling

This whole series is about getting computers to predict how physical things change (air over a wing, heat through metal, water sloshing) by learning from examples instead of hand-written formulas. One way to predict faster is to use a shrunk model that only tracks the most important patterns. This talk shows how to use a selection method called CUR—pick the most informative rows and columns from a matrix—to make these shrunk models work for complicated PDEs (rules that say how something changes place-by-place and moment-by-moment) where change isn't just proportional, and to make the code easier to build.

YouTube source · Talk page

Core Problem

A shrunk model with bases (sets of directions) that change as time goes forward can solve big PDEs by tracking only a few evolving patterns instead of tracking everything. But when the PDE has complications (change that isn't proportional) and those complications aren't simple polynomials (terms like x², x³), the cost of computing the shrunk equations becomes as expensive as solving the whole original problem. On top of that, writing the code to do this is tedious and error-prone.

First-Principles Model

Start with a PDE solution that is huge and complicated. Instead of tracking every detail, represent it as a few time-changing patterns—vectors and numbers that evolve. To find which patterns matter most, compute them by minimizing how wrong the model's guess is compared to the real answer. For complicated terms (the non-proportional parts), CUR does this: it picks the rows and columns of a matrix that carry the most information, then approximates the whole matrix using just those rows, columns, and a small computed piece where they overlap. This way, the time-changing patterns stay shrunk because you only compute the complicated terms at the informative spots you picked.

Key Claims

  • Time-changing patterns pull out the real correlations hiding in big PDE solutions.
  • These patterns are built by minimizing error as you go, not by analyzing data that was computed beforehand.
  • Shrunk models stay cheap for simple PDEs (where change is proportional) and for polynomials (sums of powers like x + x²), but non-polynomial complications force you back to full cost.
  • Non-proportional terms that aren't polynomials are especially hard to handle in shrunk models.
  • Picking which rows and columns to use (CUR selection) makes shrunk models for complicated PDEs actually stay cheap.
  • This method cuts down the amount of code you have to rewrite when applying shrunk models to new PDEs.

Important Terms

CUR Matrix Decomposition

Pick a few columns and a few rows from a huge table of numbers; compute a small connecting piece where they cross; use those to approximate the whole table.

Dynamical Low-Rank Approximation

Represent a complicated, evolving system by keeping only a few time-changing directions—compressing the information needed to describe what happens.

Time-Dependent Basis

A small set of directions that evolves during the simulation—it doesn't stay frozen, it updates moment-by-moment to stay closest to the real answer.

Sparse Interpolation

Compute complicated nonlinear terms at only a few carefully chosen spots (not everywhere), and use those spots to approximate the terms wherever you need them.

Non-Polynomial Nonlinearity

A non-proportional term you can't write as a simple sum of powers (like x + 3x² + x⁵); computing a shrunk version of it is much harder than for simpler terms.

Connections Across The Series

  • This talk continues the line of work on shrunk models: instead of just finding patterns in data, this method picks which parts of the calculation matter most and only computes those.
  • It connects to other paths for making shrunk models practical, like learning from data and adapting the shrunk model as time goes forward.
  • It also links to smarter ways of picking which data points or rows/columns to actually compute, based on which ones carry the most signal.

Practical Caution

Picking which rows and columns to keep must be done carefully: the error from the shrunk representation has to stay small. If you miss rows or columns where the non-proportional behavior is happening, the shrunk model will run fast but give answers that are wrong.

Takeaway

Making shrunk models that run fast needs two things working together: a shrunk structure (low-rank) and a way to compute complicated terms cheaply. CUR gives you the selection method that picks which pieces matter, so shrunk models for complicated PDEs can actually stay shrunk.
