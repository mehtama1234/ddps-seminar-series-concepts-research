Talk 133 · Georgia Tech

Raphael Pestourie: Input-Space Scientific Machine Learning for PDE-Constrained Optimization of Geometries

This whole series is about getting computers to predict how physical things behave by learning from examples instead of only hand-written math. This talk focuses on a smarter way to speed up design: instead of teaching a learning program (millions of little dials tuned by trial and error) to predict the full solution from scratch, feed it the design choices (like a shape) and let the physics solver do what it was built to do, while the learning program just learns how to suggest good designs faster.

YouTube source · Talk page

Core Problem

Most current approaches to learning-based physics prediction try to teach a program the entire solution to a physics rule (like how heat spreads through metal). But this wastes work: the physics solver already knows these rules perfectly. When you want to find the best shape for something—the best wing, the best lens structure—you really only need to learn which shapes are good, not re-teach the program the entire physics from scratch.

First-Principles Model

Instead of learning the full physics, stay with the numerical solver (the program that actually knows the physics rules) and teach a learning program to predict or suggest good inputs—like which shape to try next. One method, called Physics-Enhanced Deep Surrogates, learns how to speed up the simulation itself by watching patterns in what the solver computes, without replacing the solver. Another method, called HiLAB, helps search through huge lists of possible shapes when finding the best one, by teaching the learning program to guess which shapes are promising before testing them with the full solver. Both methods are tested on standard physics rules and on real design problems in nanophotonics (making tiny structures that control light).

Key Claims

  • Learning programs can speed up both simulation and the search for better designs when physics rules guide them.
  • Teaching a learning program to repredict the full physics wastes effort because solvers already know those rules.
  • A learning program can work in the space of solver inputs (the numbers you feed into the solver).
  • The numerical solver stays in charge of predicting what physics actually happens.
  • Learning programs can speed up expensive simulations by watching and copying what solvers typically predict.
  • Learning programs can efficiently search through huge numbers of possible shapes when a solver measures how good each shape is.

Important Terms

Input-Space Scientific Machine Learning

Teaching a learning program (with millions of adjustable dials) to get better at choosing inputs to feed into a physics solver, rather than teaching it to predict the physics solution itself.

PDE-Constrained Optimization

Finding the best design when you must run a physics solver for each candidate design to measure how good it is. PDE is short for partial differential equation—a rule that says how something changes from moment to moment or place to place (how fast heat spreads, how water moves).

Physics-Enhanced Deep Surrogate

A learned speedup model that watches what the physics solver predicts and learns to copy its answers faster, but still runs the real solver sometimes to stay accurate instead of guessing.

Geometry Optimization

Finding the best shape or structure by testing different designs to see which one reaches your goal—like finding the wing shape that provides the most lift.

Metasurface

An engineered surface built from millions of tiny identical bumps or structures (much tinier than a grain of salt) that bend and steer light in special ways.

Connections Across The Series

  • This talk brings together design optimization (finding the best shape), solvers you can take gradients through (a way to improve the solver by tracking how changes ripple forward), inverse design (working backward from a goal to find the input), and learning-based physics.
  • It pushes back on other talks by arguing that the physics solver does not need to be replaced—it can stay as the true physics engine while a learning program learns what to ask it.
  • It also connects to materials and nanophotonics research where the shape or structure is the main lever you can pull to change the result.

Practical Caution

This approach assumes the solver itself is correct. If the numerical solver skips some physics or gets something wrong, then the learning program will optimize towards bad designs—it will find shapes that look good to the incomplete solver, but do not work well in the real world.

Takeaway

For design problems, teaching a learning program to spot good inputs (like good shapes) is more honest and often more effective than teaching it to re-invent the entire physics solution.
