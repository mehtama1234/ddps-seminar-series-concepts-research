Talk 24 · University of Texas at Austin

Tan Bui-Thanh: Model-Constrained Deep Learning For Inference, Control And UQ

This whole series chases one goal: getting computers to predict how physical things behave by learning from examples. One approach is to write down the math rules (the laws of physics) and use them to guide the learning, so the program respects the real science while also learning from data. This talk is about embedding those physics rules directly into a learning program to solve inverse problems—figuring out hidden causes from limited measurements—and to make control decisions when you also need to measure your uncertainty.

YouTube source · Talk page

Core Problem

Many real problems need you to work backward from measurements to figure out what you can't see. Imagine measuring the temperature at a few spots and trying to figure out where a heat source is hidden inside a metal block. The catch: you get only a handful of readings, those readings contain errors, and each one depends on many hidden causes mixed together. The hidden causes (what we're trying to find) can also be enormous—thousands or millions of possibilities. If you want to be sure about your answer, you have to check thousands of scenarios, and each check means running a physics simulator step by step. That's unbelievably slow.

First-Principles Model

Start with a forward simulator: a program that takes in parameters (like: where is the heat source?) and runs the physics rules to predict what you'd measure. A physics rule is a recipe that says how something changes moment by moment or place by place—for instance, how fast heat spreads through a metal bar. Working backward (the inverse problem) means: given some measurements, find the hidden parameters that would have produced those measurements. In a Bayesian approach, the answer isn't a single number but a cloud of plausible possibilities—a probability distribution over all the parameters that fit the data reasonably well. The challenge: computing this probability cloud is expensive because you have to run the forward simulator many times. A new idea is to wire the forward simulator directly into a learning program (a network of adjustable dials that learns by trial and error) or into a fast approximation of it, so the learning respects the physics while you avoid running the simulator thousands of times.

Key Claims

  • Combining physics rules (written as equations) with learning from data (finding patterns) gives you the speed of learning plus the certainty that the physics is respected.
  • Forward problems use the physics rules to predict what you'd measure from known parameters. Inverse problems work the other way: use the measurements to back out the hidden parameters.
  • When the hidden quantities are numerous and the measurements are limited, there are endless possibilities—too many to check one by one.
  • Making a Bayesian probability cloud over the hidden parameters (showing which ones are likely) requires running the forward simulator over and over, and this is prohibitively expensive.
  • A simpler approximation can replace the expensive probability cloud by fitting it to a distribution that's quick to compute—no need to run the full simulator each time.
  • The key move is placing the physics simulator inside the learning architecture so the learning automatically respects the physics and avoids recomputing it for every trial.

Important Terms

Model-Constrained Deep Learning

A learning approach where the program's guesses are forced to obey a physics simulator or scientific equation—instead of the program guessing anything, it guesses only answers that satisfy the law.

Forward Problem

A simulator that takes in parameters (like: position of a heat source) and runs the physics rules to calculate what you'd measure.

Inverse Problem

Taking measurements and working backward to find the hidden parameters or causes—for example, finding where the heat source is by measuring temperature at a few spots.

Posterior Distribution

A cloud or spread of plausible parameter values—each one weighted by how well it matches your measurements—showing which parameters are more or less likely.

Variational Inference

A technique to replace an expensive probability calculation (running a simulator thousands of times) with a simpler, faster approximation that still captures how uncertain you should be.

Connections Across The Series

  • This talk brings together two big ideas: running physics simulators backward through neural networks (so gradients flow from the answer back through the physics) and embedding entire equations inside neural networks as layers.
  • It connects to digital twins because real digital twins need to infer the current state of a real system and measure how sure you are, not only predict the future.
  • It also connects to control because making a good control decision (how hard should the robot push?) depends on first inferring what state the system is in and how uncertain that inference is.

Practical Caution

A physics-aware learning system is only trustworthy if two things work: the forward simulator must correctly capture the real physics that matters, and the fast approximation must correctly estimate how confident you should be in your final answer. If either one fails, your downstream decisions—where should a robot move? how much material do we need?—could be wrong.

Takeaway

Inference and control need learning systems that obey the physical laws while making uncertainty computation fast enough to actually use in practice.
