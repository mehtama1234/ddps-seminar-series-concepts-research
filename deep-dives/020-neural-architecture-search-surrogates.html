Talk 20 · Argonne National Laboratory

Romit Maulik: Neural Architecture Search For Surrogate Modeling

This whole series chases one goal: getting computers to predict how physical things behave by learning from examples instead of hand-written math. One way to do that is with surrogate models—simplified programs that act like the real simulator but run much faster. The problem is that designing the architecture (the overall shape and size of a learning program with millions of dials the computer tunes by trial and error until its answers look right) takes forever and often locks you into the default choices humans happen to try first. This talk shows how to automate that design by trying thousands of different shapes and sizes, and how to use many different designs together to measure how much uncertainty there is in the prediction.

YouTube source · Talk page

Core Problem

Building a fast surrogate model (a learning program trained to mimic what a simulator does) usually means someone has to sit down and decide the overall shape and size of the neural network by hand: how many layers, how wide each layer should be, whether to include shortcuts that skip ahead, which parts should squeeze information down, how much randomness to add during training. All these choices (called the architecture, hyperparameters, bottlenecks, and symmetry assumptions) get decided once at the start, often based on whatever worked on a different problem or what the person nearest to the computer happened to build last time. That manual decision-making can eat up months of the project. And it hides better designs that nobody would naturally guess, especially for weather forecasts or autoencoders (learning programs that squish data down to find its simplest patterns, then rebuild it from those patterns).

First-Principles Model

A neural network can be drawn as a flowchart with no loops: each box is one operation (multiply, add, randomly drop some dials, jump ahead to a later box), and arrows point forward. The space of all possible networks is everything you could draw this way—varying how many boxes, how wide they are, where the jumps go, what operations each box does, how randomly things turn on and off during training, and all the numbers that control how the trial-and-error tuning happens. An optimizer like aging evolution picks candidate flowcharts, trains each one on real examples, scores how well each one predicts on held-out data it never saw, then mutates the good ones (small random changes), removes the bad ones, and repeats. After many rounds, better networks bubble up. When you keep many different trained networks from this search—not just the final winner—you can see how much the prediction wiggles when you change the network's shape. That wiggle tells you how uncertain you should be about the answer.

Key Claims

  • DeepHyper automates the search over thousands of possible neural-network shapes, sizes, and training settings across many kinds of networks.
  • Searching over architectures can find surrogate models that work well without needing the physical laws built into the network structure itself.
  • The space of all possible networks can be drawn as a flowchart showing every operation and connection the search is allowed to build.
  • Aging evolution keeps the best candidate networks, mutates them slightly, removes the worst ones, and repeats until networks stop getting better.
  • Architecture search can question default choices—like the idea that if a network squishes data down, it must rebuild in exactly the reverse way.
  • Using many different trained networks together lets you see how much the prediction changes when you pick a different network shape—that change is your uncertainty.

Worked Example

POD-LSTM surrogate for sea surface temperature forecasting on the Optimum Interpolation (OI) dataset (180×360 grid, daily data). Evolved architecture found via aging evolution (genetic algorithm on DAG encoding) shows R² ~0.95 within minutes, converging across multiple random seeds. Compared to US DoD HiCom (800 CPU-hours/day for 1-day forecast on Cray XC40) and Community Earth System Model (30-member ensemble), the POD-LSTM delivers 8-week forecasts with lower RMSE in the eastern Pacific during El Niño. Top-100 architectures post-trained on separate GPU resources until convergence.

One Level Deeper

Proper Orthogonal Decomposition extracts low-rank basis: snapshot matrix Φ ∈ ℝ^(N×m) (N DOFs, m snapshots) → SVD → truncated POD basis {φ₁,...,φᵣ}. Coefficients a(t) evolved via LSTM: a(n+1) = f_θ(a(n)) learned on training data. DAG-encoded architecture (array of integers) represents operations: variable LSTM nodes, skip connections, connection operations. Aging evolution interprets genome as architecture array, applies mutations to maximize validation accuracy or minimize validation loss, evaluates in parallel (128 nodes × 1 architecture each).

Failure Boundary

LSTMs are not systems of ODEs and lack time-integration structure, causing long-term forecast divergence after 8 steps. POD convergence is slow for advection-dominated problems (high Kolmogorov width). Convolutional autoencoders + LSTM better handle sharp advection but lose orthogonality guarantees. Cost-benefit trade-off: ~10% accuracy gain over hand-tuned LSTM may not justify HPC wall-clock investment for marginal improvements.

Important Terms

Neural Architecture Search

Automatic trial of thousands of different network shapes and sizes by a computer, instead of one person deciding the shape by hand at the start.

Search Space

Every possible network shape, operation, and training-control number that the search is allowed to build and try.

Aging Evolution

An algorithm that picks candidate networks at random, trains each one, scores how well it predicts, keeps the good ones, mutates them slightly, removes the weak ones, and repeats; it mimics how populations evolve over time.

Architecture Ensemble

A collection of many different trained networks, each with its own shape, run together on the same data; seeing how much the prediction moves when you switch between them shows you how much the network shape matters.

Asymmetric Autoencoder

A learning program that squishes data down in its first half (the encoder) and rebuilds it in its second half (the decoder), where the decoder does not have to be the mirror image of the encoder—it can be a completely different shape.

Connections Across The Series

  • This builds on earlier work showing that the shape of a reduced-order model (a simplified program that mimics the real simulator but runs faster) is something the scientific workflow should search over and optimize, not just assume at the start.
  • It ties to uncertainty and robustness: by running many different network shapes and seeing how much the prediction changes between them, you learn how much your uncertainty should be.
  • It also connects to hyper-reduction (using only a few of the most important directions in the data) because finding smaller, efficient networks means predictions run faster in real applications.

Practical Caution

Neural architecture search does not replace the need to check whether predictions make physical sense. If the search only rewards how well the model fits test data it was shown, it can find networks that look accurate on the tests but predict crazy things when deployed in the real world, or grow so huge they are impractical to run, or produce answers that violate the laws of physics.

Takeaway

The real lesson is that the shape and size of a learning program is a design choice—just like picking a solver, boundary conditions, or a method to compute things faster. Neural architecture search searches over that choice instead of hoping a human default design is good enough.
