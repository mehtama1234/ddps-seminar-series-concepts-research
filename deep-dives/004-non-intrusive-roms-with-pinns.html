Talk 4 · EPFL

Jan Hesthaven: Non-Intrusive ROMs Using Physics-Informed Neural Networks

This whole series is about making computers predict how physical things behave by learning from examples instead of only hand-written math. This talk focuses on a concrete bottleneck: when you must speed up repeated simulations but can only watch what a simulator produces, not see how it works inside (because it's old, proprietary, or too complex). One way forward is to train a neural network (a program with millions of little dials you adjust by trial and error) to predict the answer instantly. This talk shows how adding physics rules to that trial-and-error process can make the predictions more reliable when the simulator itself is hidden from view.

YouTube source · Talk page

Core Problem

Simulators that run slow step-by-step through a physical problem can be sped up by learning a compressed shortcut: instead of running the full simulation, predict the answer using a smaller set of numbers. If you have access to the simulator's internal equations, you can work out the shortcut math by hand. But in real engineering, simulators are often locked away — written by other companies, classified, or so tangled with decades of code that nobody dares to touch them. In those cases, you only see the inputs going in and the answers coming out, with no way to touch the gears inside. When problems are nonlinear (meaning the answer does not scale linearly with the input), even the best hand-derived shortcuts still force you to run expensive calculations at full scale, choking the speedup.

First-Principles Model

The goal is to build a fast shortcut: a map that takes in the problem's parameters (like wind speed or material stiffness) and directly outputs the answer as a small set of numbers representing the solution. If you can see the simulator's equations, math tells you exactly how those numbers should change with parameters. If you cannot see inside, you run the full simulator many times with different parameters and watch what outputs you get. Then you train a neural network (millions of adjustable dials) to imitate those input-output pairs. As it learns, if you also tell it the physics rules, you can nudge it to find answers that obey the laws while still matching the data.

Key Claims

  • A reduced shortcut can represent solutions to repeated parameterized physics problems using just a small set of basis shapes, giving you speed without redoing the full simulation each time.
  • Nonlinear physics creates a stubborn problem: even after you shrink the math down to those few numbers, calculating the physics terms still forces you back to the full scale of the problem.
  • When you can only observe the simulator's inputs and outputs, not its internal structure, you must build your shortcut by watching examples, not by working out the math by hand.
  • A neural network can learn the direct mapping from parameters to the small set of numbers that represent the solution in the simplified basis.
  • If the basis captures the essential patterns in solutions, the learned mapping should be smooth enough that a small neural network can pick it up reliably.
  • Physics rules built into the neural network's training can steer it toward physically sensible shortcuts rather than letting it chase any pattern that fits the data.

Worked Example

A feed-forward neural network maps PDE parameters (boundary conditions, material properties) to reduced basis expansion coefficients. For a 1D viscous Burgers equation with 2 parameters, using 50 randomly chosen data points and 8000 residual points, a small neural network (2 layers, 10-30 neurons, hyperbolic tangent activation) achieves L2 error of 1e-2 to 1e-3 after 5,000 iterations using Adam optimizer followed by L-BFGS. For a 2D Stokes flow with non-uniform domain mapping, training 200-300 solutions for a 2D Navier-Stokes reduced model with 6 basis functions, the neural net predicts velocity and pressure with 1000x speedup compared to full Galerkin projection, though accuracy is limited to roughly 10e-2 percent error.

One Level Deeper

The non-intrusive ROM uses a neural network Θ to learn the map μ → α(μ) where μ are parameters and α are expansion coefficients in a reduced basis V. Loss function combines data mismatch L_data = ||u_measured - Σ α_i v_i||² and PDE residual L_PDE = ||∂u/∂t - N[u]||² evaluated via automatic differentiation. For time-dependent problems, an LSTM network learns the memory term: the convolution kernel K accounting for discarded high-modes through projection P onto the reduced space, outputting the correction term to the Galerkin ROM that enforces energy balance. The projection error decomposition breaks total error into: (1) finite-element approximation error (PDE discretization), (2) reduced basis projection error ||u - Π_V u||, and (3) neural network approximation error for the parameter map.

Failure Boundary

Accuracy plateaus around 1e-2 to 1e-3 error due to high-dimensional non-convex optimization even with adaptive learning rates; spectral accuracy (1e-4 or better) is difficult to achieve. When reduced basis doesn't well-represent solution manifold (bad linear space), neural networks cannot compensate—garbage in, garbage out. For long-time integration without memory correction, reduced ROM solutions drift rapidly and can show completely wrong amplitude/phase; adding LSTM correction gains 4-6 orders of magnitude accuracy. Training data volume and neural network size involve overfitting plateau: too few snapshots or oversized networks cause spurious overfitting visible in validation curves beyond ~25 neurons for small problems.

Important Terms

Intrusive shortcut

A speed-up technique that requires you to look at the simulator's equations or rewrite parts of it.

Non-intrusive shortcut

A speed-up built entirely from watching the simulator's inputs and outputs, without changing or examining how it works inside.

Basis number

A small set of numbers that, when multiplied by key patterns in the solution, reconstruct an approximate answer without storing the full, huge array of values.

Nonlinear bottleneck

The cost or barrier that appears when the physics rules themselves depend on the solution in complicated ways, forcing you back to the full scale even in a sped-up version.

Overfitting in neural shortcuts

When a neural network learns the specific examples it saw during training so well that it fails on new examples, like memorizing test answers instead of understanding the concept.

Connections Across The Series

  • This talk describes the core workflow that threads through the whole series: collect examples from the full simulator offline, identify the essential patterns, then use a fast predictor online.
  • It places neural networks in a concrete engineering role: solving the specific problem of hidden solvers and nonlinear bottlenecks, not as a replacement for numerical simulation but as a tool to sidestep particular obstacles.
  • It connects to design workflows because the speedup only pays off when you must run many different parameterized versions of the same physics problem in sequence, such as exploring design options or optimizing a component.

Practical Caution

This shortcut only works if two things are true: first, the full solution must have a simple underlying shape that you can capture with just a few essential numbers, and second, the learned map from parameters to those numbers must work reliably on new parameter values it has never seen before. Machines are notorious for one mistake: making the neural network too large or complex without feeding it enough examples. When you do that, the network memorizes the specific training examples rather than learning the true pattern, so it fails on fresh parameters you did not show it during training.

Takeaway

The central lesson is practical: neural networks become your tool when classical mathematical shortcuts hit a wall, especially when the solver is only available as a closed program you cannot modify, or when the physics creates expensive side calculations that even shortcuts cannot avoid. Use this method to sidestep those specific obstacles, not to replace numerical simulation itself.
