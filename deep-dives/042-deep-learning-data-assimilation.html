Talk 42 · Rice University

Ashesh Chattopadhyay: Deep Learning Meets Data Assimilation

This whole series is about getting computers to predict how physical things behave—air, water, heat, structures—by learning from data rather than only hand-written step-by-step math. Weather and climate are especially hard because they are chaotic: tiny errors become huge mistakes in days. This talk shows how to combine learning (a program with millions of dials tuned by trial-and-error to match patterns) with a crucial first step called data assimilation: using real noisy measurements and old predictions to estimate a good starting point before you forecast forward.

YouTube source · Talk page

Core Problem

Weather and climate span many scales—from tiny eddies to global patterns—and are chaotic: a small change now can lead to a completely different outcome later. You cannot forecast by starting from 'perfect truth' because real measurements are noisy (each one is a guess plus error), sparse (we measure only a few spots), and uneven (some places have many sensors, others have none). Whether you use a traditional step-by-step physics model or teach a program to learn the patterns, both have mistakes. Before you can forecast anything, you must solve the hard first problem: turning noisy spotty measurements and an imperfect guess into a good starting state.

First-Principles Model

Data assimilation is a way to combine what you already believe (prior knowledge) with new measurements to get a better estimate of the real state right now. Imagine you know roughly what the weather is (a background forecast from yesterday or an hour ago), but also some new thermometer and pressure readings just came in. Data assimilation asks: how do I weight these two sources fairly? It gives more trust to sources that have proven reliable before. Deep learning fits in as follows: a program can learn to predict missing small-scale details (like turbulence or cloud effects that the coarse model skipped), or learn to correct forecast mistakes, or learn to fix noisy measurement errors, or even learn to update many parallel guesses using data (a method called ensemble Kalman filtering, where 'ensemble' means many copies). The key danger: if you let the learning program run free, small starting mistakes can amplify fast in chaotic systems, breaking predictions weeks ahead. So the learned parts must respect the laws of motion.

Key Claims

  • Weather and climate are hard to forecast because they spread across many sizes of motion and because tiny changes now grow into huge mistakes later.
  • You cannot start a forecast from a perfect state because real sensors give noisy spotty readings, and a model (whether traditional math or learned) is never perfectly right.
  • Data assimilation merges a rough forecast from the model with new real-world measurements to estimate a usable starting point.
  • Learning programs can discover how tiny-scale processes (like water droplets and air movement) affect the big-scale weather by studying high-resolution simulations or lots of measurements.
  • The smartest forecasts pair learned prediction with traditional numerical models rather than throwing away the physics entirely and trusting only the learning program.
  • Keeping predictions physically consistent and using ensemble methods (running many parallel forecasts and updating them together with data) are the tools that make learned predictions reliable in real operations.

Worked Example

For a two-layer quasi-geostrophic flow (canonical mid-latitude dynamics model with 36,000 states), a regular ensemble Kalman filter using 20 numerical ensemble members produced a divergent filter with normalized RMSE trending upward. Switching to 5,000 ensemble members yielded convergence with error decreasing at each assimilation step. The hybrid deep learning ensemble Kalman filter traded 10 numerical ensembles (cost ~1 solver step each) for 2,000 data-driven ensembles (cost ~1/200 of a numerical solve), achieving approximately 4× reduction in forecast error over 60-day cycles with no increase in total computational cost.

For weather re-analysis at 2,048 dimensions (low-resolution ERA5), an SO(3)-equivariant neural network trained on 12-hourly data achieved 5 days of forecast skill (0.6 ACC threshold), compared to ~4 days for standard UNet. Using hierarchical multi-model data assimilation with virtual observations (treating 12-hourly forecasts as synthetic observations to update hourly predictions), the filter converged for 4,000 ensemble members with correlation coefficient >0.7 even under high observational noise.

One Level Deeper

Ensemble Kalman filtering computes Kalman gain K = PH^T(HPH^T + R)^-1 where P is background error covariance, H is observation operator, and R is observation noise. High-dimensional systems suffer from rank deficiency when using few ensemble members—the sample covariance P becomes corrupted by sampling error causing spurious long-range correlations. The hybrid approach: (1) compute P from thousands of cheap data-driven ensemble forecasts; (2) compute background forecast from fewer accurate numerical ensembles; (3) combine via analysis state x^a = x^b + K(y^obs - Hx^b).

Deep learning forecasting uses autoregressive integration: given state u_t, predict u_{t+Δt}. For spatiotemporal weather fields, SO(3)-equivariant transformers maintain rotational variance by embedding spatial transforms in latent space. Training horizon determines prediction skill: 12-hourly models have longer forecast skill (slower error growth) than hourly models due to coarser temporal sampling. Virtual observations exploit this multi-scale difference: intermittently assimilate high-fidelity 12-hourly predictions as synthetic observations y_virt to correct drift in hourly forecast chains.

Failure Boundary

Pure data-driven ensemble Kalman filters fail when the surrogate model loses accuracy beyond its training horizon. A data-driven model trained for 1-day forecasts cannot reliably predict covariance structure at 5+ days, causing filter divergence. Additionally, convolutional architectures fail on weather systems because they lack rotational equivariance—they cannot distinguish between a low-pressure anomaly above a high-pressure zone (potentially triggering extreme events) from the reverse configuration, leading to misclassification of critical dynamic patterns.

Data-driven weather models exhibit unphysical long-term drift and climate instability even when forecast skill is 5+ days; they cannot reproduce observed climate statistics. Transfer learning between climate regimes (e.g., pre- vs. post-climate-change initial conditions) requires retraining because the model shows distributional shift sensitivity—Reynolds number changes or parameter shifts cause complete loss of generalization. Sparse, noisy observations coupled with a high-dimensional system (10^8 states in operational weather) forces impossible ensemble sizes; practical systems use localization and inflation hacks rather than principled solutions.

Important Terms

Data Assimilation

A technique that blends a model's rough prediction with noisy real-world measurements to produce a better estimate of what the system is actually doing right now.

Analysis State

The improved state estimate you get after you merge observations into an older forecast prediction.

Background Forecast

The model's prediction before you add corrections based on new observations.

Ensemble Kalman Filter

A data assimilation method that runs many parallel predictions simultaneously and updates all of them together using new measurements, so you can track how uncertain your predictions are.

Hybrid Forecasting

Combining a traditional physics-based model (the slow hand-written step-by-step math) with learned data-driven parts (a program that tuned itself by trial-and-error) to get faster and better predictions.

Connections Across The Series

  • This talk builds on physics-guided learning because the structure of how you design a learning program matters enormously when small starting errors can explode as the system evolves forward.
  • It also touches neural operators and reduced-order models: any learned piece must cooperate with state estimation, not just predict far into the future on its own.
  • The lecture pairs with discussions of uncertainty because the starting state is uncertain (your measurements are noisy), and that uncertainty is a root cause of forecast errors down the line.

Practical Caution

A learning program trained on clean made-up data can seem perfect in a lab test—but collapse when you feed it real noisy spotty measurements or run it forward for many days. If you ignore how errors grow in chaotic systems and build a pure learning predictor without checking each step against physics rules, the program will confidently make garbage predictions.

Takeaway

Prediction always starts with state estimation: you cannot skip the hard work of turning messy data into a good starting point. For chaotic physical systems like weather, learning what the system will do next and learning how to set up the starting state correctly are two sides of the same coin—you must solve both together.
