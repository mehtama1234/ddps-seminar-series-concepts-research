Talk 118 · University Hospital Freiburg

Marius Zeinhofer: Infinite Dimensional Optimization for Scientific Machine Learning

This whole series is about getting computers to learn how physical things behave from examples instead of only using hand-written math. One approach is to use learning programs (programs with millions of dials the computer tunes by trial and error until their answers look right) to solve physics problems. This talk focuses on how to design the trial-and-error process: the key idea is to think about the problem at the level of complete curves or functions first—the shapes you're really trying to learn—before you worry about how many dials your program has.

YouTube source · Talk page

Core Problem

When we build a learning program to solve physics problems, we usually think of it as trying to pick the right values for millions of little dials. But this misses something important: the real problem we're solving is about finding the right shape or curve that describes how something behaves. Thinking only about dials—just numbers—hides the actual geometry (the shape) of the problem, making it hard to build methods that work well on big problems or that actually make sense given what physics tells us.

First-Principles Model

The proposal is: think about your problem in terms of complete functions or curves first, then figure out how many dials you need. Here's how it works. You pick an algorithm designed for the function-level problem (the curves you want to find). Then you translate that algorithm into concrete adjustments for your program's dials using the tangent space—this is a fancy name for all the tiny, allowable changes you can make to the curves your program can represent given its architecture. This approach can re-derive (show why certain methods work) existing scientific learning algorithms and adapt the natural gradient method, including a speedy way to approximate it using Kronecker products, for solving large problems.

Key Claims

  • You can understand scientific learning optimization by thinking of it as working with complete functions or curves, not just lists of numbers.
  • You should design your trial-and-error method at the function level first, then convert it into instructions for tuning your program's dials.
  • The best algorithms are built at the function level before you decide how to represent them in a real program.
  • The translation from functions to dial adjustments uses something called the tangent space—the set of tiny changes you can make given your program's architecture.
  • Well-known scientific learning algorithms turn out to be special cases of this function-space thinking.
  • You can adapt advanced methods like the natural gradient (which respects the true shape of your problem) for big scientific learning problems by using Kronecker products to keep it fast.

Worked Example

Illustrative: Infinite-dimensional optimization framework applied to PDE-constrained design: minimize ∫Ω (u - u_target)² dx + α||control||² subject to ∂u/∂t + (u·∇)u + ∇p = control in Ω. First-order optimality yields adjoint equations: ∂λ/∂t + u·∇λ + (∇u)ᵀλ + ∇q = u - u_target. Gradient of objective w.r.t. control is J'(control) = -λ. Discretizing with finite elements yields ~100K-1M unknowns; direct optimization on this scale requires carefully tuned preconditioners and adaptivity to avoid ill-conditioning that manifests as slow convergence or sensitivity to initialization.

One Level Deeper

PDE-constrained optimization in function spaces: state u(x,t) evolves via F(u, control) = 0 (PDE); goal is min J(u, control). Lagrangian L = J + ∫λᵀF dt enforces constraint at each point. Adjoint λ satisfies ∂L/∂u = 0, a backward PDE. Gradient ∇_control J computed from ∂L/∂control. Key: infinite-dimensional structure preserves regularity—adjoint operator is formal dual of linearized PDE. Discretization (FE in space, time-stepping) must be compatible: adjoint discretization dual to primal, or adjoint-consistency error pollutes gradient. Reduced-order methods project both primal and dual to same POD basis—preserves duality structure if basis from uncontrolled dynamics.

Failure Boundary

For turbulent flows (high Re), adjoint sensitivity becomes highly chaotic; small perturbations in primal trajectory cause exponential growth in adjoint over long time horizons, rendering gradient estimates unreliable beyond short time windows. Nonconvexity: multiple local minima in control landscape; adjoint-based gradient descent gets trapped. Discretization errors in primal PDE propagate through adjoint computation; any unresolved scales corrupt gradient. Reduced-order adjoint degrades when control explores regions outside training basis span—unobserved modes feedback through adjoint and amplify error. For systems with weak observability (some states weakly affect objective), adjoint weights vanish numerically, causing gradient starvation. Parameter estimation (unknown coefficients in PDE) with adjoint requires identifiability analysis—poorly identified parameters have near-zero gradient.

Important Terms

Infinite-Dimensional Optimization

Trying to find the best complete function or curve, not just the best values for a list of numbers. 'Infinite-dimensional' means you're working with whole functions (which have infinitely many degrees of freedom) instead of just a finite list.

First Optimize, Then Discretize

Design your trial-and-error method at the level of complete, smooth, perfect functions first; only after that, break it down into concrete steps a computer can run. This often gives you better, more reliable algorithms.

Function Space

Imagine a huge catalog of all possible curves or functions you could draw on a graph. That catalog is a function space. Each element in it is a complete function, not just a single number.

Natural Gradient

A way to adjust your program's dials during trial and error that takes into account the true shape and distances in the landscape you're exploring, instead of just moving in the steepest downhill direction.

Kronecker-Factored Approximation

A trick to estimate how sharply the landscape curves (curving information) using a special product structure that keeps calculations fast, so you can use it on huge problems where a full estimate would take forever.

Connections Across The Series

  • This talk bridges what we know about optimization (how to improve a guess over and over), the building blocks of learning programs, and how to train programs that solve physics problems.
  • It complements talks about embedding equation solvers inside learning programs by instead focusing on the geometry (the shape and structure) of how the program learns itself.
  • It connects to first-principles ideas by showing that training a learning program is just a computer version of a function-level optimization process.

Practical Caution

Thinking in terms of complete functions can make your algorithms clearer and more honest, but running them on a real computer still depends heavily on the exact shape of dials you pick for your program and how carefully you translate the math into actual code. A rushed or careless translation can wipe out all the benefits you gained from thinking in function space.

Takeaway

The main lesson is that when designing how to improve a scientific learning program, you should first think about what the problem really looks like in terms of complete functions or curves, only after that should you decide how many dials your program needs.
