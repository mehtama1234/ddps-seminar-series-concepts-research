Talk 75 · Caltech / NVIDIA

Anima Anandkumar: Neural Operators On Function Spaces

This whole series is about getting computers to predict how physical things behave — air, heat, water, weather — by learning from data instead of only hand-built equations. This talk focuses on a specific approach: teaching a learning program to take an entire pattern (like a map of temperatures across a region) as input and directly produce another pattern (like how those temperatures change) as output. Because this method learns to work with patterns themselves rather than with numbers on any one particular grid, it can switch between different grid sizes and different regions, and runs thousands of times faster than traditional step-by-step equation solvers.

YouTube source · Talk page

Core Problem

Real scientific systems — weather, climate, materials, earthquakes, nuclear reactions — don't fit neatly into a fixed list of numbers. They describe how things vary across space (temperature changes from place to place) or time (heat spreading through metal). A standard learning program expects its input to be the same list of numbers every time (like always 1000 temperature readings). But weather happens on many different grids, on different regions of Earth, with different edge conditions (like "air temperature stays at this value at the boundary"). This means retraining a standard program for each new situation is slow and expensive.

First-Principles Model

A traditional equation solver works like this: you give it a starting condition (like "the metal bar begins at room temperature") and a rule (like "heat spreads by diffusing"), and it steps forward in small time increments to predict what comes next. A neural operator learns to do the same job but by recognizing patterns directly: it watches many examples of (starting condition) → (final answer) pairs and learns the pattern that links them. The crucial insight is that this pattern-recognition lives in a space of functions (complete field solutions, not individual numbers), which means the learned rule doesn't care which grid spacing you use or which geographical patch you're working on — the same pattern works everywhere.

Key Claims

  • Neural operators learn patterns that directly map input patterns to output patterns, which is what equations between fields actually describe.
  • When learning targets patterns (functions) instead of grids, it works well across many scales and many different situations.
  • Real uses include weather forecasting, climate modeling, predicting earthquake behavior, and modeling materials.
  • A well-built operator can work on new problems it never trained on, as long as those problems are in the same family.
  • Neural operators run many thousands of times faster than traditional solvers that step through equations one time increment at a time.
  • The advantage comes from matching the learning method to the real mathematical object you need: a function-to-function map, not a general-purpose learning program.

Important Terms

Neural Operator

A learning program trained to take a complete pattern (like a temperature field across a region) as input and produce another pattern as output, rather than converting a single list of numbers to another single list.

Function Space

A mathematical library of all possible patterns for a type of field — imagine all the different ways temperature or pressure could be arranged across your region of interest.

Zero-Shot Generalization

The ability to work correctly on a new problem the learning program has never encountered before, without additional training or adjustment.

Multiscale Process

A situation where what happens depends on activity at many different time and size scales happening together — for example, both tiny molecular vibrations and large planetary-scale wind patterns affect weather.

Operator Learning

Training a model to recognize the pattern that connects input conditions (like starting temperature and forcing) to output solutions (like final temperature everywhere) for a whole family of related problems.

Connections Across The Series

  • This talk introduces neural operators as a core building block that appears in Kaushik Bhattacharya's work on operators that work across multiple scales and system types.
  • It connects to talks on faster substitutes for equations because both develop quick, reusable prediction maps, but operators work directly on field patterns instead of compressing them to a few numbers first.
  • It ties closely to weather and data assimilation talks because both need fast pattern-to-pattern predictions for atmospheric systems that cover whole regions.

Practical Caution

Neural operators are not automatic. When you test them on problems they've never seen before — a new region, different boundary conditions, or slightly different physics rules — they can fail completely. The architecture itself doesn't guarantee the model will work on these new cases; you have to actually run real tests and check. Generalization only works if the new problem is similar enough to what the learning program studied.

Takeaway

The lesson is this: choose what you teach the program to learn based on what the problem actually asks for. If you want a map-to-map predictor (a temperature map becomes a new temperature map), teach it to recognize that map-to-map relationship, not just memorize individual answer snapshots. Designing the learning to match the true structure of what you're solving makes everything work better.
