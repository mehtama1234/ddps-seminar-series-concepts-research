Talk 73 · Emory University

Matthias Chung: Big Data Inverse Problems

This whole series is about getting computers to predict physical behavior by learning from examples instead of only hand-written math. This talk focuses on a common real-world puzzle: you have noisy measurements (data with errors in it) of something you want to find, but many different solutions could fit that data. The challenge is to add stabilizing assumptions—like 'the real answer is sparse, meaning most values are zero'—and to use learning programs (computers with tunable dials) to pick the right amount of stabilization when working with massive datasets.

YouTube source · Talk page

Core Problem

An inverse problem means working backward: you see measurements (like shadows or echoes) and want to recover what caused them (the object or space). But working backward is tricky. First, noise in the measurements (random errors, wobbles) gets amplified—like trying to amplify a whisper and hearing mostly static. Second, many different answers can fit the same noisy data equally well, so the problem becomes ambiguous. Third, with truly large datasets, old mathematical methods become too slow. One solution is to assume the true answer is sparse—that it has only a few important values and the rest are zero or tiny. But even with sparsity, you must pick a regularization strength: how much to penalize non-zero values to force sparsity. Too little, and noise pollutes the answer. Too much, and you lose real signal. Choosing this strength automatically is hard.

First-Principles Model

An inverse problem is a balance between two things: fitting the measurements you collected and respecting prior knowledge about what the answer should look like. If you assume the true quantity is sparse—it has only a handful of large values in some chosen coordinate system—then you can add a penalty based on absolute values of coefficients (called L1 regularization) to encourage the program to zero out unnecessary values and keep only the essential ones. To handle huge datasets, one method, called variable projection, works by analytically or implicitly hiding some variables so the computer solves a simpler problem. Another path is to train a learning program (a neural network with millions of tunable dials) to look at the data and the inverse problem itself and automatically propose a good regularization strength.

Key Claims

  • Modern data analysis, machine learning, and uncertainty quantification all depend on being able to solve inverse problems fast enough.
  • When datasets and models get very large, many standard statistical methods become impractically slow.
  • Many real inverse problems have answers that are sparse, meaning most values are zero or negligible.
  • L1 regularization (penalizing absolute coefficient values) is a widely used way to enforce sparsity in compressed sensing, dictionary learning, and imaging.
  • Variable projection, a rearrangement of the optimization math, offers a new path to handle sparse inverse problems.
  • Learning programs can infer good regularization choices by training on examples of inverse problems.

Worked Example

Image deblurring: gaussian kernel blur on 256×256 image + noise. Generalized LASSO with total variation (D=difference operator): min ||Ax-b||₂² + λ||Dx||₁. Variable projected augmented Lagrangian (VPAL) vs ADMM on 512×512, 1024×1024 images: VPAL 7-9× faster wall-clock time (~2-3min vs 14-21min for ADMM) despite similar iteration counts. Learning regularization λ via DNN: offline train on 10k synthetics with noise levels [10⁻⁶,10⁻³]; online prediction from data noise→λ; DNN achieves optimal λ within 2% vs UPRe/GCV methods.

One Level Deeper

VPAL algorithm: reformulate min_x,y ||Ax-b||₂² + λ||y||₁ s.t. Dx=y. Form augmented Lagrangian ℒ(x,y,u)= ||Ax-b||₂² + λ||y||₁ + u^T(Dx-y) + (ρ/2)||Dx-y||₂². Variable projection: eliminate y via shrinkage (soft thresholding) → reduced problem in x: min_x ||Ax-b||₂² + λ||D^T shrink(Dx,λ/ρ)||²; gradient of projected problem drops y terms. Update: ∇_x ℒ_projected = 2A^T(Ax-b) + 2D^T(D·)·shrink(·), requires only A,D matrix-vector products (no matrix inversion). Convergence: proved via variable projection theory (Golub-Pereyra) + augmented Lagrangian (Powell). Neural regularizer: DNN(b)→λ maps noise observation to optimal regularization; training via ground-truth solutions.

Failure Boundary

Poorly chosen λ (10× too large or small) causes 3-5× slowdown or divergence. ADMM sensitive to inner solver tolerance; inexact solve breaks theory. Large scale (>4D MRI, 5D cardiac): memory O(m n) for A matrix; VPAL still needs A^T A system solves. Nonlinear operators A: VPAL requires Jacobian-vector products; loses advantage over ADMM. DNN regularizer fails on out-of-distribution noise (e.g., trained on Gaussian, tested on impulse noise) or operators A_test ≠ A_train (transfer risk ~10-20% error on new physics). Very ill-posed problems (κ(A)>10⁸): all methods unstable; implicit regularization needed.

Important Terms

Inverse Problem

A process of working backward: you observe indirect measurements (shadows, echoes, signals) and try to recover the hidden causes (the object, space, or signal that produced them).

Ill-Posed Problem

A problem where solutions might not exist, might be non-unique (many different answers fit equally), or might swing wildly if the data shifts even slightly.

Sparse Representation

An encoding where only a small number of values are large or nonzero; most are zero or negligible, so the answer is 'simple' in that coordinate system.

L1 Regularization

A penalty that adds up the absolute values of all coefficients and pushes their sum down; this reward sparsity because setting a coefficient to zero costs less than keeping it nonzero.

Variable Projection

An optimization technique that hides or eliminates some variables through math, leaving a simpler problem to solve so the computer can work faster and avoid getting stuck.

Connections Across The Series

  • Inverse scattering, adaptive reduced-order models, and Bayesian calibration—other talks in this series—all solve inverse problems under uncertainty, and all must choose regularization strength.
  • Regularization is not a late fix or afterthought; it is the central way to encode prior knowledge and make inverse inference stable when noise is present.
  • This talk bridges scientific machine learning with classical computational mathematics, showing that learned regularization and sparse methods extend rather than replace the long history of regularization theory.

Practical Caution

Just because a learning program picks a regularization strength does not mean you have solved the problem. The program learned its strategy on one set of inverse problems—perhaps ones with a particular type of noise, or particular kinds of true answers. If the real inverse problems you face later have different characteristics, the learned strategy may fail because it encoded assumptions that no longer apply.

Takeaway

Inverse problems always need stabilizing assumptions to keep answers from wobbling wildly due to noise. Sparsity and learned regularization are two tools to encode those assumptions when datasets grow very large.
