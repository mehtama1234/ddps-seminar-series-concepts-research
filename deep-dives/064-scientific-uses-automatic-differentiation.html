Talk 64 · Harvard University / Google Research

Michael Brenner: Scientific Uses Of Automatic Differentiation

This whole series is about getting computers to predict physical behavior by learning from examples instead of only hand-written math. This talk focuses on something deeper: a tool called automatic differentiation — a way to compute gradients (the direction and slope to move toward a better solution) through any computer program — might be more useful to science than the learning programs themselves, because it turns scientific discovery into a general optimization problem.

YouTube source · Talk page

Core Problem

Many scientific problems hide inside optimization: solve a PDE (a rule that says how something changes from moment to moment or place to place, like how heat spreads or air pushes), design a material with specific properties, find an unstable water or gas flow state (one that doesn't stay put by itself), figure out the sequence of steps a molecule takes during assembly, understand how organisms grow, or design a way to drive a system far from equilibrium (away from balance) to achieve something specific. Traditionally, each problem needs hand-written math for gradients (the direction to change inputs for a better result), custom tricks for working backward through the math, or brute-force search trying every combination. This limits the size and flexibility of the problems scientists can tackle.

First-Principles Model

Automatic differentiation means you can take any program — a simulator, a measurement of how far you are from a goal, a model of a physical process — and ask: if I change the inputs slightly, how does the output change? You get back gradients (which direction and by how much to adjust things). If you write a scientific problem this way, you can do large-scale optimization: state what you want to achieve, write the computation, compute the gradients automatically, and search for designs, hidden states, or governing structures.

Key Claims

  • The tools running machine learning, especially automatic differentiation, can matter more to science than the learning programs themselves.
  • Automatic differentiation enables large-scale optimization for scientific discovery.
  • Automatic differentiation can support new algorithms for solving PDEs.
  • The same approach can design energy landscapes and the sequences molecules take during self-assembly.
  • Optimization can discover unstable solutions that organize fluid instabilities.
  • Automatic differentiation-based scientific computation can extend to organismal development, nonequilibrium statistical mechanics, fluid properties, and protein self-assembly.

Worked Example

Smoke dynamics inverse problem (autograd example): optimize initial velocity field so smoke evolves into target image (peace sign). Full solution in ~15 lines of Python code via autograd. Burgers equation on 32x mesh spacing coarser than training resolution: learned scheme outperforms classical finite-volume, flux-limiter, and WENO schemes. Komogolev turbulence (2D, Reynolds 1000, 2048² training grid, 64² coarse test): learned interpolation-based scheme achieves 80x speedup vs DNS while maintaining accuracy to 3 Lyapunov times. Vorticity correlation: learned model performs between 512² and 1024² resolution (compared to raw 64² direct solve). Statistics (spectra) match higher-resolution schemes. ML inference cost: 12.5x more FLOPs than baseline CFD but only 12x slower wall-clock on TPU V4 (better utilization). Speedup calculation: 10³ mesh refinement × 10 time-stepping factor ÷ 12 ML overhead = ~833x net speedup. Higher Reynolds number generalization (1000→4000): scaling law (1/√Re in 2D) yields valid model after mesh rescaling; performance degrades slightly but enables substantial upscaling.

One Level Deeper

Automatic differentiation: unroll computation graph, apply chain rule to obtain exact forward and backward derivatives without numerical approximation. Adjoint method for PDE-constrained optimization: solve forward problem (x_t), then backward adjoint problem (λ_t) for design derivatives independent of parameter count. Loss function minimization via gradient descent on learned neural network interpolation coefficients. Update rules with learnable stencil coefficients C_NMK (nonlinear functions of velocity field) replacing polynomial interpolation. Finite-volume time stepping with learned flux interpolation. Three architectural choices: (1) pure ML emulator (full neural network update rule); (2) learned interpolation (NN-based flux computation + physics update); (3) learned corrections (standard scheme + NN correction term). Chart-space vorticity projection; spectral analysis via Fourier coefficients.

Failure Boundary

Coarse-grid interpolation without learning: classical finite-volume produces instabilities; flux limiters add excessive diffusion and smear shocks. Chaotic flow sensitivity: beyond ~3 Lyapunov times, correlation with DNS decays (fundamental prediction limit for chaotic systems, not method-specific). Pure ML emulators fail generalization: good on training forcing/Reynolds number but collapse on unseen forcing patterns, larger domains, or different Reynolds numbers. Learned interpolation generalizes better but requires fine-tuning per problem class. Memory overhead: storing full computation graph for autodiff requires more RAM than adjoint methods. Numerical solver (Jack CFD) currently limited to single GPU/TPU—higher Reynolds scaling requires distributed implementation. Runtime scaling n/k^{d+1} with ML overhead factor 12 (pre-factor C_ML/C_physics); even with 10x grid coarsening in 3D, speedup only ~1000x before hitting memory/compute wall mentioned for turbulence (~Re^{9/4} grid points needed). Model interpretability lost: learned stencils are black boxes (though Burgers experiment recovered WENO-like behavior post-hoc).

Important Terms

Automatic Differentiation

A computational method that exactly computes how outputs change when inputs change, by applying the chain rule (a calculus rule for how derivatives stack through composite operations) through every step of a computer program.

Large-Scale Optimization

Solving problems with thousands or millions of choices to make, made practical by computing gradients (directions to move to improve the result) efficiently instead of guessing randomly.

Energy Landscape

A map showing the energy at every possible state a system could occupy, which determines which states are stable and how the system transitions between them.

Kinetic Pathway

The series of steps a system goes through as it evolves, such as the sequence of molecular clusters that form as a material assembles.

Unstable Solution

A mathematically valid state or trajectory that would fall apart if disturbed slightly, but which still organizes the behavior of nearby states.

Connections Across The Series

  • This lecture grounds differentiable programming, embedded closure learning, DPC, and inverse design talks by showing why differentiability matters.
  • It reframes machine learning infrastructure as scientific infrastructure: when scientific workflows become differentiable, they become optimizable.
  • It also connects to equation discovery and digital twins because differentiable programs can search over mechanisms, designs, and hidden dynamics.

Practical Caution

Computing gradients through a program does not mean your goal makes sense scientifically or that the math stays numerically stable. Automatic differentiation gives you directions to move; scientists still need valid models, constraints that capture reality, and experiments to verify the answer works.

Takeaway

Automatic differentiation changes what scientists can optimize over. When any scientific computation becomes differentiable, it becomes optimizable — turning scientific problems into a single general language: define your goal, encode the physics, compute gradients, and search for solutions.
