Talk 136 · Lawrence Livermore National Laboratory

Youngsoo Choi: Defining Foundation Models for Computational Science: Toward Clarity and Rigor

This whole series is about getting computers to predict how physical things behave by learning from examples. This talk asks: what exactly should we call a foundation model for science, and shows one concrete way to build one by combining the old-school math methods that engineers have trusted for decades with modern trial-and-error learning.

YouTube source · Talk page

Core Problem

In language and vision, foundation models work—a single huge learning program, trained once on lots of data, can then be twisted to solve many different tasks. But in computational science (predicting how fluids flow, how materials break, how climates shift), people are starting to use the term foundation model without really agreeing on what it means. This opens the door to marketing hype. Different problem families—fluids, materials, climate, design optimization, uncertainty quantification—each have their own demands. A program that calls itself a foundation model for science needs to prove it can be reused across different problems, scaled up to harder cases, and still respect the rigor that scientists and engineers demand.

First-Principles Model

A real foundation model for computational science should do three things: work on many different types of problems without starting from scratch each time; handle bigger, harder versions of the same problem without falling apart; and keep the mathematical bones and discipline of the old numerical methods (the formulas engineers have used for decades to carve space into pieces and solve equations locally) while adding smart learning components that adapt automatically from data. The talk lays out what properties matter and introduces one path forward: Data-Driven Finite Element Method, which keeps the structure of classical finite-element solvers but teaches part of them to learn from data instead of relying only on hand-written formulas.

Key Claims

  • The term foundation model is spreading from language and vision into computational science.
  • The field needs a shared, rigorous definition or the term loses all meaning.
  • Three criteria matter most: generalization (does it work on new problems?), reusability (can I adapt it without retraining from scratch?), and scalability (can it handle bigger, harder cases?).
  • A scientific foundation model must be judged against what scientists actually need, not just against machine-learning test scores.
  • Data-Driven Finite Element Method is one concrete path: it borrows the structure and mathematical rigor of classical numerical methods and teaches them to learn from data.
  • The goal is clarity and rigor—laying out what counts and what does not—not picking one fixed design that works for all science.

Worked Example

Illustrative example: guided manifold learning on porous media flow. Training set of 50-200 simulations with varying permeability fields (lognormal, correlated). Deep network learns low-dimensional latent space where solutions concentrate. Prediction speedup 10-50x on unseen permeability realizations. Compared to linear POD, nonlinear manifold captures tensor-train decomposition structure of heterogeneous problems.

One Level Deeper

Manifold linearization: decompose solution u = u_lin + δu where u_lin satisfies linearized PDE around reference parameter. Deep network learns δu in low-dim space. Jointly optimize reference state and manifold basis to minimize prediction error across parameter range. For parabolic PDEs (diffusion-dominated), manifold typically 5-20 dimensional despite 1000+ DOF discretization. Guided means incorporating physics constraints: enforce boundary conditions strongly in loss, penalize non-physical solutions.

Failure Boundary

Method fails when nonlinearity dominates over linear component (high Rayleigh number, strong convection). Manifold assumption breaks at bifurcation points. Extrapolation beyond training parameter range unreliable. Ill-posedness if reference state poorly chosen.

Important Terms

Foundation Model

A learning program trained once on a large and diverse collection of data, then adapted to solve many different downstream tasks by further adjustment rather than retraining from scratch.

Computational Science

Using mathematical equations, computer simulations, and numerical recipes to predict and understand how real physical systems behave—fluids, solids, temperature, motion, chemical reactions, climate patterns.

Data-Driven Finite Element Method

A method that divides space into tiny regions and solves equations piece by piece, like classical finite elements, but replaces some of the hand-written formulas with a learning program that adapts to match actual data from experiments or simulations.

Reusability

Whether a model can handle many different problems and tasks after being trained or designed once, without having to rebuild and retrain it from the ground up each time.

Scalability

Whether a model can handle much larger problems, finer detail, more complex physics, or more expensive calculations without crashing or losing accuracy.

Connections Across The Series

  • This talk ties together the earlier talks in the series on reduced-order models (smaller, faster approximations), neural operators (learning rules written as operations), materials science, and the broader thread about foundation models for science.
  • It pushes back against handwaving by insisting that foundation model must mean something precise and specific to each field, not just a borrowed term from language and vision.
  • It also grounds foundation models in classical numerical analysis and operator networks, treating the mathematical structure of scientific computation as non-negotiable, not an optional add-on.

Practical Caution

Size alone does not make a foundation model. A program can be huge and still useless for science. The label should only apply if someone has shown the model actually transfers to new problems, generalizes beyond its training data, and follows the standards that domain scientists expect.

Takeaway

A foundation model for science must be defined by what scientific problems it can actually solve and reuse, not by analogy to big language models alone.
