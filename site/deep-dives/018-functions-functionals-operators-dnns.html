Talk 18 · Brown University

George Karniadakis: Approximating Functions, Functionals, And Operators Using Deep Neural Networks

This whole series is about teaching computers to predict how physical things behave by learning from examples instead of only hand-written math. This talk jumps to a harder problem: a learning program (a huge bank of dials the computer tunes by trial and error) can learn single guesses, but real physics often needs to learn an entire solution map—a rule that takes a function (like an initial temperature across a bar) and spits out another function (like the temperature everywhere later). This talk shows how to teach neural networks to do that using DeepONet, which uses two smaller learning programs working together—one that digests the input function, one that knows the output location—to build the full solution map.

YouTube source · Talk page

Core Problem

Many real physics problems do not have one fixed rule that takes a handful of numbers and gives an answer. Instead, there are huge families of related problems where the input itself is a function—an initial shape, a forcing pattern, a property changing from place to place, or a record of measurements from sensors. Simulation means learning a solution operator, a rule that takes one function as input and produces another as output. A learning program needs to handle this: the same governing equations with different starting states, different boundaries, different geometries. Standard neural networks were built to turn numbers into numbers. Here we need to turn functions into functions.

First-Principles Model

Start with three kinds of maps. A function takes one point and gives one value—the temperature at a spot, the cost of a stock. A functional takes a whole function and gives one number back—the total energy stored in the system, the cost summed across time. An operator takes a whole function and gives another whole function—the PDE solver that takes initial temperature and gives future temperature everywhere. DeepONet builds an operator by using two learning programs working together. The branch network takes the input function (often represented as measurements at a few specific points) and squeezes it down to a short list of numbers that capture its essence. The trunk network takes the location where you want an answer and also produces a short list of numbers. Multiply the two lists together, add them up, and you get the predicted value at that location. Repeat for every location and you have the full output function. When data are scarce or noisy, add the physics rules themselves as loss terms—penalize the learning program if its answers break the governing equations.

Key Claims

  • Real scientific learning often relies on physics rules or priors when data are limited or noisy, not just raw examples.
  • PINNs work especially well for inverse problems because measurements help steer the trial-and-error tuning toward the right answer.
  • Operator learning is broader than a single guess; it learns the entire mapping from input function spaces to output function spaces.
  • DeepONet learns operators by combining a branch network (which ingests the input function through measurements) and a trunk network (which encodes the output location) to predict values everywhere.
  • How you represent the input function—which points you measure, which basis functions you choose—shapes whether the learned rule will work on new data.
  • Neural operators can power digital twin models, where a learned fast rule replaces or speeds up slow simulation for large systems.

Worked Example

DeepONet learns integral operators from data: 10,000 functions sampled from Gauss random field, 100 sensors per function input representation. MSE converges to 10^-5 (excellent accuracy) with exponential convergence on interior; drops to 1/√n algebraic convergence after network width saturation. Bubble dynamics (Rayleigh equation): maps pressure difference Δp to radius r(t) evolution, handles oscillation and viscous decay across three regimes (continuum, stochastic, optimistic) seamlessly. Hypersonic flow chemistry (Mach 8-10): beats CFD solver 100,000x using only 100 trajectories for training; predicts species evolution and velocity avoiding stiff chemistry solver.

One Level Deeper

Operator approximation via branch-trunk network: branch net φ(u) encodes infinite-dimensional input u evaluated at m sensor locations; trunk net ψ(y) maps output query location y; output G[u](y) = Σ_k φ_k(u)·ψ_k(y) (inner product in latent space). Extends single-layer universal operator theorem (Chen-Chen) to deep networks composed with nonlinearity g: G ≈ σ(ψ)·σ(φ) alternating. Key: one sensor per function sufficient; input space representation (GRF, orthogonal polynomials) critically affects convergence speed (2 orders magnitude difference with fractional polynomial basis).

Failure Boundary

Curse of dimensionality: beyond ~20 input parameters, data requirements explode unless problem has low effective dimension (sensitivity-based dimensionality reduction needed). Non-compact input spaces (e.g., Gaussian random fields) require careful sampling strategy; uniform random sampling breaks down without active learning. Model fails catastrophically on discontinuous operators (multi-scale bubble nucleation regime switch); requires separate training on each physics regime or hybrid multi-fidelity approach. Cannot extrapolate beyond training distribution: shown on Mach 13 case only succeeds via fine-tuning with 5 new data points, not from Mach 8-10 training alone.

Important Terms

Functional

A rule that takes a whole function as input and produces a single number as output—for example, a rule that sums up temperature across an entire bar, or totals energy over all time.

Operator

A rule that takes one function as input and produces a different function as output—the most common example is a PDE solver, which takes initial conditions and produces the solution at all future times and places.

DeepONet

A learning program designed to learn operators by splitting the job: one smaller program (branch) digests the input function (often as measurements at specific points), another (trunk) knows the output location, and together they predict the value there.

Sensor Representation

The choice of a few measurement points to stand in for an entire function—how the learning program is told what the input function looks like during training and when making predictions.

Physics-Informed Regularization

Adding the governing equations themselves into the loss signal—penalizing the learning program if its answers violate the physics rules—so it learns to respect them even when data are scarce.

Connections Across The Series

  • This talk is the main anchor for operator learning in the early seminar sequence and extends the PINN talks from solving a single PDE to learning the entire solution operator that solves a whole family of PDEs.
  • It connects to graph simulation and ROM-net because all three ask how to represent physical states compactly and build fast maps between them.
  • It links to hybrid twins because a learned operator can serve as the fast learned component inside a larger twin that mixes learning and classical simulation.

Practical Caution

Operator learning still depends on which input functions the learning program saw during training and how those functions were represented. A DeepONet trained only on small initial temperatures may fail badly on large ones. A network trained with measurements at ten sensor points may not transfer to a different sensor layout. A learned rule for one geometry may not work on a shifted geometry. Always test on input functions that look different from training.

Takeaway

The lesson is that real science and engineering often need to learn maps between spaces of functions, not just guess single numbers. Building neural operators—programs that take functions to functions—is how we extend learning to the full complexity of physics.
