Talk 29 · Cornell University

Christopher Earls: Gaining Mechanistic Insight Through Learning Green's Functions

This whole series is about getting computers to predict how physical things behave by learning from data and examples instead of only hand-written equations. This talk shows how you can learn what's called a Green's function — a special response pattern that captures how a system reacts to a poke — and use that pattern to reverse-engineer the hidden rules that govern the system and understand what's actually happening inside.

YouTube source · Talk page

Core Problem

Deep learning programs can predict what a system will do next, but real science needs to understand why it happens. When the equation that controls the system is unknown or too hard to write by hand, you can learn the solution operator — a map that says 'given this input, the output will be that' — sometimes called a Green's function. Once you have that map, you can study it like a fingerprint to read off what physical laws might be hiding in the data.

First-Principles Model

For a simple (linear) rule — one where changes add up straightforwardly — a Green's function is the answer you get when you poke the system with a single quick impulse, like a hammer tap. Once you know that single-poke answer, you can reconstruct the response to any other input by carefully adding up (integrating) the Green's function's response scaled by that input, like building the answer from overlapping echoes. Teaching a computer to learn this kernel (the pattern inside the integral) from observed data gives you a compact, human-readable operator that can tell you what hidden equation is probably controlling the system, and which predictions you can test in reality.

Key Claims

  • Patterns in how systems actually respond to inputs contain clues about hidden mechanistic structure.
  • The goal is not just to predict what happens next, but to learn response patterns and compact integral kernels that can be decoded back into rules.
  • Green's functions are a classical, time-tested bridge connecting single impulses to the equations that govern complex behavior.
  • Deep learning can take the old Green's function idea and apply it to new problems and kinds of data.
  • Operators pulled out by learning can be examined like fingerprints to find features that suggest what mechanisms are at work.
  • This method is related to other neural operator techniques but distinct in how it prioritizes operator interpretability.

Worked Example

For the 1D Poisson equation with Dirichlet boundary conditions, empirical Green's function learning recovers the analytical Green's function with 0.01 relative error (noise-free data). When Gaussian white noise with standard deviation equal to the mean response is added to every measurement, error grows to 0.03 relative error—modest degradation despite significant contamination. The 1D Helmholtz equation (k=15 on unit interval) achieves 0.03 error; the Burgers equation at θ=10 reveals antisymmetry and fine structure in the learned Green's function matching the self-adjoint operator property.

A multi-physics domain (one quarter Helmholtz, three quarters Poisson) shows the learned Green's function shadows both diffusion-like structure (top right) and wave-like structure (bottom left) in different regions. Manifold interpolation at unobserved parameter θ=7 (using library entries at θ=1,5,10) yields interpolated Green's function matching the truly learned one at θ=7 with 0.04 relative error—demonstrating data-free prediction.

One Level Deeper

Green's function theory: for linear operator L, the Green's function G(x,x') satisfies L*G = δ(x-x'). Solution u = ∫ G(x,x')f(x')dx' + homogeneous boundary contribution. Spectral decomposition via Fredholm theory: G = Σₖ (conjugate(eigₖ)·eigₖ)/λₖ. Empirical approach replaces orthonormal eigenbases with POD modes extracted from data ensembles. For each parameter θᵢ, collect snapshots under random Gaussian process excitations, compute SVD to get left singular vectors (spatial POD modes), and solve for diagonal coefficient matrices Σₖ minimizing least-squares fit between observed and reconstructed data.

Deep rational neural networks further relax self-adjoint requirement: learn G and homogeneous solution u_h as separate 3-2 rational networks (rational functions replace ReLU/tanh activations) trained on superposition loss: ∫G⊗f + u_h ≈ observed_solution. Rational poles cluster at singularities in the true solution, providing mechanistic insight. Training uses only 100 cause-effect pairs via Gaussian process excitations with tight covariance kernels—over-sampling guarantees rank-k approximation almost surely per randomized linear algebra theory.

Failure Boundary

Method requires self-adjointness for spectral decomposition (empirical phase). Advection-dominated or non-self-adjoint operators violate this—though deep learning extension removes this constraint. Passive observation (no control over excitation) reveals only a narrow subspace of the Green's function; Gaussian process excitations must have high-frequency content (small covariance kernel width) to ensure rank-k coverage. With sparse or missing data (e.g., excluding shock region), recovery degrades but rational networks show surprising robustness—poles still cluster at discontinuities via extrapolation through nearby observations. Computational bottleneck: rational network training requires second-order optimization (L-BFGS combined with Adam) for convergence near singularities; first-order gradient descent fails. Systems of PDEs (Stokes flow, coupled ODEs) are tractable but require learning block-matrix Green's functions; coupling strength determines conditioning.

Important Terms

Green's Function

The answer you get when a linear rule is poked once with a single quick impulse; acts as a response pattern you can combine and layer to build the answer to any other input.

Solution Operator

A map that says: given a source, forcing, or input, here is the corresponding output or system response.

Integral Kernel

A function placed inside an integral (a summing operation) that converts input data into output data.

Hidden PDE

An unknown rule that controls how a system changes, inferred indirectly by studying the data, never given to you upfront.

Mechanistic Insight

Understanding the actual gears and levers behind observed behavior — the physical or mathematical mechanism — rather than just predicting what happens.

Connections Across The Series

  • This talk brings together operator learning and interpretability: the operator you learn should teach you something real about what physics is hidden underneath.
  • It connects to nonlocal kernels because both involve learning integral kernels by studying how systems respond to inputs.
  • It also complements equation discovery methods by learning the solution pattern itself rather than trying to manually pick and name individual PDE terms.

Practical Caution

A learned Green's function works best for simple, straightforward systems where changes combine by addition. When the system has wild, chaotic nonlinearities where small changes cause big surprises, you have to test the learned operator carefully or only use it near the specific conditions where you trained it.

Takeaway

An operator you can actually read and interpret — one that you learn from data — is often more useful for doing science than a pure prediction box, because it points back toward the actual mechanism driving the system.
