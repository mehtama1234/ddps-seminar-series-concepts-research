Talk 94 · University of Michigan

Elnaz Rezaian: Data-Driven Balancing Transformation For Predictive Model Order Reduction

This whole series is about getting computers to predict how real things behave by learning from examples instead of only hand-written rules. This talk focuses on a specific trick: when you have a system with many levers you can pull (inputs) and many readouts you can see (outputs), how do you build a smaller, faster prediction that still tracks which inputs steer the system and which outputs show what's happening — and how wrong could your small model be? A method called balanced truncation answers this by keeping the parts of a system that matter for control and seeing what happens, then throwing away the rest.

YouTube source · Talk page

Core Problem

Small, fast models are great for real engineering — but they often fail because they miss how inputs wire to outputs, or they give no promise about how far off they'll be. Balanced truncation gives you a mathematical guarantee of accuracy, but building it the straightforward way, or building it from real data you measure, gets slow when you have many inputs and many outputs.

First-Principles Model

Balanced truncation works by finding which internal states the system can reach from the inputs (reachability: which directions can you steer the system?), which internal states show up in the outputs (observability: what can you see in the readouts?), then erasing states that are neither reachable nor observable. Data-driven versions like ERA build small models by watching how the system reacts to sharp input pulses. The result is a model tuned specifically for control and carries mathematical promises about its error, but to scale it up when you have many inputs and outputs, you need tricks: tangential interpolation (probe the system in specially chosen directions), output decomposition (split the readouts into smaller independent chunks), and gappy POD-style approximations (fill in measurements you don't have).

Key Claims

  • Balanced truncation comes from control theory and is built exactly for steering systems.
  • Data-driven balancing uses measured reachability and observability matrices (numbers that capture which directions the system can reach and which show up in outputs, built from real data) and minimum realization theory (finding the smallest model that matches what you measured).
  • Mathematical error bounds make balanced models trustworthy for real predictions.
  • The eigensystem realization algorithm is a direct, data-driven path to balanced truncation.
  • ERA predicts well on stiff fast-burning chemical flows and sound-driven systems.
  • Many input-output channels mean more computation, so you need tangential interpolation, output decomposition, and gappy POD.

Worked Example

One-dimensional reacting flow with species transport and reaction (Navier-Stokes + species equations) was discretized to yield ~200 states. A unit impulse at the inflow excited the system; impulse response snapshots (77 pressure, 50 temperature, 19 species modes) captured 99.99% of input-output energy in ~150 Hankel matrix rows. The resulting era ROM used 2 orders of magnitude larger timesteps than the full model before becoming unstable, enabling fast predictive simulation. Offline cost (impulse runs + matrix operations) completed in under an hour; online evaluation was 100× faster than full-order CFD.

One Level Deeper

Eigensystem realization algorithm (era) constructs the Hankel matrix H from impulse responses; shifted Hankel H' groups the same data one timestep forward. SVD gives H = U Σ V^T; the ROM state-space matrices emerge as A = U^-1 U_shift, B = sqrt(Sigma) V^T[1,:], C = U[1,:] sqrt(Sigma). No intrusive access to system matrices required—pure data-driven. Tangential interpolation projects onto low-dimensional input/output subspaces, reducing computational cost by 1.7×; output domain decomposition runs separate (finer-resolution) ROMs on critical regions (sharp gradients at boundaries).

Failure Boundary

Era demands impulse responses that capture transients; if the system has lightly damped oscillatory modes with long decay times, gathering sufficient snapshots becomes expensive. For unstable systems or those near bifurcation points, reachability and observability gramians are ill-conditioned, and truncation arbitrarily selects which modes to keep. Multi-input multi-output systems with many boundary conditions multiply the training burden (one impulse per input channel). Nonlinear systems require linearization about nominal states, so the ROM is valid only locally; far from linearization points, accuracy degrades rapidly.

Important Terms

Balanced Truncation

A model reduction method that erases internal states the system barely reaches from its inputs and barely shows in its outputs, keeping only the states that matter for steering and observing.

System Gramian

A table of numbers that measures how reachable or observable a dynamical system is, based on the rules that govern how it moves.

Eigensystem Realization Algorithm

A data-driven method that builds a small model by analyzing measured impulse responses (how the system reacts to sharp input pulses) to find the smallest equivalent model.

Markov Parameter

A single number in the sequence of impulse-response values; the full sequence lets you rebuild how the system transforms inputs into outputs.

Gappy POD

A method to reconstruct the full behavior of a field from measurements that are scattered or incomplete, using patterns learned from complete snapshots.

Connections Across The Series

  • This lecture adds a control-theory view of small models to the broader model reduction thread.
  • It connects to predictive models, reverse engineering, and digital twins because error bounds are needed before you can trust the model in the real world.
  • It also builds on CUR and adaptive ROM talks by prioritizing input-output balance instead of compressing only which states vibrate the most.

Practical Caution

A small model can still mislead you if it erases states that matter for outputs or that your control actually needs to move. Always reduce the model for the specific input-output task you care about, not just to remove the states with the least energy.

Takeaway

The core lesson is that small predictive models should protect what the system can be steered toward and what you can see in the readouts, not just which parts wiggle the most.
