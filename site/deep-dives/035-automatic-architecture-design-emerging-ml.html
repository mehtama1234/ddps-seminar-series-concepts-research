Talk 35 · Carnegie Mellon University

Misha Khodak: Automatic Architecture Design For Emerging Machine Learning Tasks

This lecture explores how to automate the process of adapting neural network designs so they work on new scientific tasks, beyond the hand-tuned convolutions built for images.

YouTube source · Talk page

Core Problem

We have successful neural network designs that were carefully tuned for images, but real scientific problems involve sequences, graphs, differential equations, and other distinct structures. Inventing new building blocks by hand for each new domain is slow and needs expert knowledge; standard neural architecture search might only try different network connection patterns, missing the chance to discover the right operations needed for a specific task.

First-Principles Model

An architecture encodes what kinds of patterns a network can learn: convolution limits how weights are shared across space. XD-operations expand this by creating flexible neural operations that can capture the same useful constraints while still being searchable for different domains. This turns architecture design into a transfer problem: find or search for operations that match the structure of a new task.

Key Claims

  • Hand-tuned neural networks sped up traditional machine learning but don't move easily to new domains without task-specific operations.
  • New tasks like learning on graphs, processing sequences, and solving differential equations need matching neural operations.
  • XD-operations generalize the useful constraints of convolutions while letting you express more.
  • You can treat architecture design as an automated search over operations.
  • The best architecture depends on how much data you have and the problem structure.
  • Searching over both the connection pattern and the specific operations at once is possible but computationally hard.

Important Terms

Architecture Transfer

Taking successful design patterns from one task and adapting them for a different task.

XD-Operation

A type of neural operation that generalizes the core useful constraints of image convolutions to work on many different problem types.

Degree-of-Freedom Constraint

A structural limit on model parameters that builds in sharing, locality, symmetry, or other built-in learning preference.

Topology Search

Searching for the best way to connect neural operations together in a network.

Architecture Design

Choosing the neural operations and how to connect them in a way that defines what the model can do.

Connections Across The Series

  • This talk adds to the neural architecture search lecture by focusing on the operations themselves, not just how they are wired together.
  • It ties to graph networks, Fourier neural operators, and differential equation solvers because the architecture must match the shape of your data.
  • It reinforces the series theme that learning preferences built into a model often decide whether it can generalize or just memorize.

Practical Caution

Automating architecture search can make finding good designs faster, but it has no way to know what matters scientifically unless you put that directly in how you measure success. Accuracy, computational cost, training stability, and whether predictions make physical sense should all guide the design process.

Takeaway

The core insight is that architecture is a language for encoding learning biases. Automatic design searches for the right biases that fit a new scientific problem.
