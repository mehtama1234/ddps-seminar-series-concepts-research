Talk 128 · Georgia Institute of Technology

Sung Ha Kang: Identifying Differential Equations from Single Observation with Numerical Methods

This whole series is about getting computers to predict how physical things behave by learning from examples instead of only hand-written math. Often you try to find the hidden rule that governs a system by running it many times and comparing results. This talk asks: what if you have just one messy recording of how something changed over time? Can you still work backward to discover the rule?

YouTube source · Talk page

Core Problem

To figure out the rule governing a system, you usually collect lots of separate runs or have exact measurements of how fast something is changing. With only one noisy, messy recording, three things become very hard: figuring out how fast things are changing at each moment (taking derivatives), choosing which pieces to include in your rule, and solving for how much each piece contributes. Small mistakes in one step get magnified in the next.

First-Principles Model

Start by guessing what the rule might look like: a mix of simple building blocks like powers of the measurement (x, x squared, x cubed) plus different rates of change (derivatives). Write these guesses as columns in a table. Then solve a math problem that asks: which combination of these columns, weighted just right, matches your one messy recording? The talk covers several strategies: IDENT (a direct method), smoothing out noise before measuring derivatives, subspace pursuit (a way to pick the most important building blocks), and weak form (using integrals of the data instead of exact point-by-point values, which is more stable when data is noisy). There is also group subspace pursuit, which picks related building blocks together rather than one at a time.

Key Claims

  • The challenge is finding the rule that governs a system when you have just one messy recording taken over time.
  • Write candidate building blocks as columns in a table, using data that you already have.
  • Use sparse methods or structured math to find which blocks matter and how much each one contributes.
  • Cleaning up noise before measuring rate of change makes those measurements more trustworthy.
  • Integral-based methods work better than point-by-point approaches, especially with heavy noise and higher derivatives.
  • Group subspace pursuit picks clusters of related building blocks at once, instead of one at a time.

Worked Example

Given one noisy time-dependent data set u(x,t), the goal is to recover the PDE u_t = f(u, u_x, u_xx, ...) with no training and no second recording. They build a feature ('dictionary') matrix of candidate terms -- constant, u, u^2, u_x, (u_x)^2, u_xx, and so on, up to dictionaries that reach 190+ terms (some tests use 35, 56, or 330 columns) -- where every derivative column is approximated (ENO scheme, guaranteed second-order accurate) and b = u_t is likewise approximated. For a Burgers equation with 8% noise, plain LASSO (L1) returns the wrong support: it zeroes out the true u*u_x term and lights up three unrelated terms. Denoising the data once with moving-average least squares first, then L1, brings back the right candidates.

L1 alone is still not enough, so a second model-selection step -- time-evolution error -- is added. From the surviving nonzero terms (say constant, u, u*u_x) they enumerate the 7 candidate PDEs those terms can form, fit each by least squares, then take the initial condition and numerically re-evolve every candidate forward with small delta t; whichever best matches the data at the end (and at intermediate times, multi-shooting style) is selected. Only then are coefficients recovered by a final least-squares fit on the chosen support. This backbone -- set up the linear system with good denoising, identify support with sparsity plus model selection, recover coefficients by least squares -- recovers Burgers up to about 30% noise; viscous Burgers (with diffusion) is harder, only about 5% noise, because higher-order derivatives amplify noise.

Later variants push further: successive denoising (denoise again after each differentiation) plus subspace pursuit and cross-validation extend viscous-Burgers to higher noise; a weak-form version reaches useful recovery at 100% noise, recovering coefficients like 0.99 and 0.98 against a true value of 1 (L2 coefficient error ~0.03).

One Level Deeper

The core linear system is F a = b, where F is the feature matrix (each column an approximated candidate term evaluated on the data), a is the sparse coefficient vector, and b = u_t. 'Support' means which entries of a are nonzero (which terms are in the equation); 'coefficient value' means their magnitudes. Sparsity alone (LASSO) fails under noise because thresholding is arbitrary and the answer depends on lambda, and in a nonlinear PDE you cannot ask term-by-term whether each belongs -- terms must be tested as a set. So model selection is grounded in numerical-PDE convergence: a correct equation, re-evolved with smaller delta t, must approach the data; a wrong term makes the re-evolved solution drift, and multi-shooting sums that mismatch over several short windows (fast and parallel).

Denoising is treated with order guarantees: moving-average least squares preserves approximation order (a third-order-accurate approximation of a smooth function stays third order after smoothing), and successive denoising / smooth-differentiation denoises again after each derivative -- for a degree-s polynomial with accuracy at least s-1, recovery of order s-1 is provable. The sensitivity analysis shows the difficulty scales with equation order: the noise-amplification denominator grows for higher-order derivatives, so fourth/fifth-order PDEs are intrinsically harder to identify under noise.

The weak form removes derivatives from the data: multiply the PDE by a smooth test function and integrate by parts so all derivatives move onto the (known, smooth, Gaussian-like) test function, turning differentiation into numerical integration -- a denoising effect. This makes the identification error less dependent on the underlying equation's order. Refinements include error-normalizing and column-normalizing the weak feature matrix for conditioning, subspace pursuit (solve for k=1,2,3,... best columns and pick by model selection), narrow-fit (fit coefficients only in high-dynamic regions of u, u_x), and trimming (drop columns contributing under a 0.05 threshold to u_t). A Fourier-domain variant restricts to the theoretically meaningful low-frequency band and helps multi-mode data at high noise. Varying-coefficient PDEs use finite-element bases per coefficient with group-sparse subspace pursuit.

Failure Boundary

Trust drops as the underlying equation's order rises and as noise grows, because approximating higher derivatives amplifies noise -- plain Burgers survives ~30% noise but viscous Burgers only ~5% in the original method. The sparse-regression step is fragile when the feature columns are coherent (highly correlated with each other): with a 330-column dictionary, correlated columns make any L1/LASSO pick essentially random, and even subspace pursuit only returns the least-residual choice, not a guaranteed-correct one. Restricted-isometry-type conditions fail exactly here, which is why they lean on subspace pursuit plus time-evolution/cross-validation rather than L1 alone.

The method is stated to struggle in 3D and with varying coefficients: audience testers report that in 3D the feature matrices become severely ill-conditioned and rank-deficient, and across 20+ sparse solvers the results are 'all over the place.' Weak-form and Fourier-form gains also require periodic boundary conditions -- non-periodic data must be padded/flipped, which injects a false gradient at the boundary that only stays harmless if most of the dynamics is interior. And everything hinges on the data being rich enough: a 'boring' 3D data set yields little, while single-observation, high-order, high-noise cases remain intrinsically hard.

Important Terms

Equation Identification

Working backward from a recording of how something changed to uncover the mathematical rule that caused that change.

Feature Matrix

A table where each column holds one candidate building block (like x, x squared, or a derivative), each column calculated at every point in your data.

Subspace Pursuit

A method that narrows down a long list of building block candidates to pick just the most important ones.

Weak Form

Rewriting the rule as an integral equation (summing up areas under curves) instead of requiring exact values at every single point, which makes the answer more stable when measurements are noisy.

Denoised Differentiation

Smoothing out the noise in a recording first, then measuring how fast it is changing, rather than measuring rate of change on the raw, jittery data.

Connections Across The Series

  • This talk applies tools from finding equations as formulas (symbolic regression), using integrals for stability (weak-form discovery), picking the right few pieces from many candidates (sparse recovery), and measuring rate of change from data (numerical differentiation).
  • It extends earlier talks on WSINDy and WENDy by addressing the hardest version: when you have only one recording.
  • It connects to the broader goal of finding equations automatically from data, where making the equations readable and working with scarce, messy measurements are both critical.

Practical Caution

Finding an equation from one measurement depends heavily on which building blocks you include in your guess and how you model the noise. If you find a rule with only a few terms, that does not mean it is the true rule—you must test it on a completely separate recording to check.

Takeaway

Working backward from a single, messy recording to find the hidden rule only works well if you use smart techniques: pick a small, focused set of building blocks, clean up the noise first, use integral-based methods instead of point-by-point calculations, and always test your answer on fresh data.
