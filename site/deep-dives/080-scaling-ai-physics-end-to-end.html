Talk 80 · Purdue University

Yexiang Xue: Scaling Up AI-Driven Scientific Discovery

This whole series asks: can computers learn how physical things behave by studying examples instead of relying only on hand-written math? This talk tackles one core challenge: when you want a learning program to discover the physics rules themselves AND simulate them to check its guesses, the computation becomes huge. The trick is to make the physics equations themselves part of the learning program (so you can send error signals backward through them) and then skip computing the parts that don't change, using fast shortcuts like random projections and smart grouping tricks.

YouTube source · Talk page

Core Problem

Teaching a learning program to discover physics rules from real measurements creates a tangled loop: you measure something, run a simulation to predict what should happen, compare to reality, and backtrack through the simulation to figure out which dials to turn. The simulation itself—a program that steps physics rules forward moment by moment to predict what happens next—can run for hours or days. And sending error signals backward through all those steps is often even slower than running the simulation forward in the first place.

First-Principles Model

The core idea: treat the physics simulation as if it were a regular layer inside the learning program (with millions of tiny dials the computer tunes by trial and error until answers look right). This means you build the physics equations so that when you send error signals backward through the dials, you can compute how sensitive each dial is to the error. Then scale it: notice that only a tiny portion of the simulation actually changes from one moment to the next, so compute only those pieces. Group elements by how their neighborhoods behave (using a trick called locality-sensitive hashing—a shortcut that links similar patterns without computing everything) and use random projection (a technique that reduces a huge pile of numbers into a smaller pile while keeping the important patterns) to shrink which parts even need computing.

Key Claims

  • Learning programs that discover physics are slow because current tools do not wire the physics equations into the learning loop as a single connected chain.
  • Sending error signals backward through a physics simulation often costs more time than running the simulation forward.
  • Physics equations can be written so that error signals travel backward through them like they would through any other part of the learning program.
  • When error signals flow backward through physics equations, huge simulations become trainable inside the learning workflow.
  • Locality-sensitive hashing speeds up physics equations by finding groups of elements that behave similarly and computing only once per group.
  • Random projection and searching through hand-picked equation forms can discover physics equations that are sparse (only a few terms matter) and decompose (break into independent pieces).

Worked Example

Nano void evolution in copper under heavy ion irradiation at 350°C was tracked from in-situ TEM videos. A recognition neural network extracted void positions and sizes from pixel data at each frame; a neural differential equation predicted future void movement and size change. Training on just a few annotated frames from the experimental video, the combined system extrapolated to predict new void configurations. Random projection compressed 0.05× the original dimensionality with negligible accuracy loss, enabling offline training despite terabytes of experimental data collection.

One Level Deeper

The framework chains pattern recognition (encoder extracting PDE variables from raw video) with neural differential equations (u_dot = N[u], solved via backprop through ODE solver). For sparse systems, random projection premultiplies the loss by a zero-one matrix R; this groups sparse loss terms, yielding L_projected = ||R(observed_update - predicted)||^2. Theory guarantees the projected loss is a constant-factor approximation to the original. The loss function itself is sparse across space and time (most domain regions unchanged), so the projection mostly hits zeros, reducing computation without information loss.

Failure Boundary

When void clusters suddenly burst (discontinuity in evolution), the continuous neural ODE ansatz cannot track the instant of rupture; predictions before rupture remain good but miss the catastrophic event. Camera noise and segmentation errors corrupt the PDE variable extraction, and neural networks may learn to interpolate rather than obey physics. For sparse systems where the projection accidentally groups non-zero terms together, the squared grouping nonlinearly distorts the loss, biasing the optimization. Generalization to new materials or temperatures beyond training fails because the learned PDE is specific to the training conditions.

Important Terms

End-To-End Scientific Discovery

A single learning loop where the computer builds new equations, tests them with simulation, checks them against real data, and uses the results to rebuild better equations—all connected as one chain.

Differentiable PDE Solver

A program that computes how physics unfolds (rules that say how things change from moment to moment or place to place) in a way that lets error signals travel backward through each step, so the computer can see which dials to turn.

Locality Sensitive Hashing

A shortcut that groups items together based on how similar they look (without checking every pair), used here to find clusters of physics elements that behave alike and compute those clusters once instead of each element separately.

Sparse PDE Update

A pattern where only a few parts of the simulation actually change in meaningful ways at each time step; the rest stay the same, so skip computing them.

Random Projection

A technique that squeezes a huge set of numbers down to a smaller set while keeping the main patterns intact, like taking a 10,000-item list and summarizing it to 100 key ideas without losing the gist.

Connections Across The Series

  • This lecture builds on automatic differentiation (the trick computers use to send error signals backward through their dials) and extends it to make physics equations trainable inside learning programs.
  • It pairs with talks about learning neural solvers and neural operators by showing how to speed up both the forward simulation and the backward error signals at the same time.
  • It continues the thread of finding hidden equations in data by tying it to actual simulation: instead of just guessing equations that fit, you embed the physics into the learning loop itself.

Practical Caution

This approach has real walls. Your computer has limited memory, so huge simulations overflow. Some equations are 'stiff'—they resist stable numerical calculation, like trying to predict a wobbling building with a crude formula. Real measurements are messy and biased. And fast backward gradients help only if the physics equations you discover and the solver actually describe reality, not noise.

Takeaway

To build learning programs that discover physics rules at scale, you have to write the equations in a way that error signals can flow backward through them, and you have to skip computing anything that doesn't matter.
