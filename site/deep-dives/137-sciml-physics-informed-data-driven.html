Talk 137 · Texas A&M University

Ulisses M. Braga-Neto: Scientific Machine Learning: From Physics-Informed to Data-Driven

This whole series asks: can a learning program predict how physical things behave (heat spreading, air flowing, structures flexing) by studying examples instead of hand-built equations? This talk explores the different ways to do it—some start by telling the learning program the laws of physics, others just show it solution data and let it find the pattern.

YouTube source · Talk page

Core Problem

When you need a program to predict physical behavior, you have choices. You can write down the physics rules (a set of equations describing how things change), but that takes effort and only works if you know the rules. Or you can show the program lots of examples and let it learn the pattern, but it might learn the wrong thing if the examples don't cover all the situations you care about. Different methods make different bets on this tradeoff—some mix the physics rules with learning, others focus only on learning from data.

First-Principles Model

The two main approaches are: (1) Physics-informed methods, such as a learning program that is also told the physics rules—where in the domain (the space and time we are studying) you can check whether the rules hold. You pick certain spots and measure how badly the rules are broken there (the residual), then penalize the program for these rule-breaks as it learns. This way the program has to respect both the data examples and the physics. (2) Data-driven operator learning, which finds the mathematical map—the transformation that takes input conditions (like temperature at the start, or pressure on edges) to the solution (like heat throughout the bar, or flow around the wing)—directly from examples, without necessarily writing down the equations at all. The idea is that if you have enough examples of inputs and solutions, the learning program can detect the pattern and apply it to new inputs, even if no one writes down the rules explicitly. These methods use very different approaches and work better in different situations.

Key Claims

  • Learning programs can predict how physical things behave by combining machine learning with scientific computation for simulation, discovering hidden rules, and solving inverse problems (figuring out what caused observations).
  • Physics-informed methods like PINNs became popular because they make it straightforward to add physics rules into the learning process.
  • Operator learning is a newer approach that focuses on learning directly from solution data without explicitly coding up the equations.
  • Operator learning can work even when you don't know or can't afford to write down the exact rules.
  • Physics-informed and data-driven approaches have different strengths—one wins when equations are reliable, the other when data is abundant.
  • Plasma turbulence is one real-world problem where these methods get tested.

Important Terms

Scientific Machine Learning

Using learning programs (neural networks or other statistical methods) to solve the problems that scientists and engineers normally solve with hand-written equations: predicting how physical systems evolve, finding rules from measurements, or figuring out what caused observed data.

PINN

A learning program (neural network) that learns from examples while also being penalized for breaking the physics rules—so it has to respect both the data and the equations as it tunes its millions of dials.

Physics-Informed Gaussian Process

A statistical model that learns from data while also incorporating the physics rules as constraints, giving you not just a prediction but also a measure of uncertainty.

Operator Learning

Teaching a program the transformation that takes input conditions (like starting temperature, or boundary forces) to the solution (how heat spreads, how stress flows), so it can predict solutions for new inputs without needing to solve the equations from scratch each time.

Collocation

Checking that your physics rules hold by testing them at specific chosen points spread throughout the domain (like measuring if the heat equation is satisfied at 100 spots across the bar).

Connections Across The Series

  • This talk brings together earlier talks in this series: physics-informed neural networks, neural operators, learning from data when equations are unknown, and building fast predictors that stand in for expensive simulations.
  • It sharpens the question running through the whole series: where does the physics come from—from equations you write, from the shape of your program, or from the data you learn from?
  • It connects to talks about learning from data by showing how moving physics into the dataset (instead of writing equations) changes what the learning program can and cannot do.

Practical Caution

The idea that 'the physics is hidden in the data' only works if your examples actually cover the real situations you will face and if they truly show the physics, not just noise. If you train a learning program on examples from one temperature range or one type of flow, then ask it to predict something far outside that range, it may fail badly because it never saw examples like that.

Takeaway

Different SciML methods place physics in different places: some write the rules into the training process (physics-informed), some build the physics into the shape of the program (architecture), and some rely on the data itself to contain the physics signature.
