Talk 19 · DeepMind

Alvaro Sanchez-Gonzalez And Tobias Pfaff: Learning Physical Simulation With Graph Networks

This whole series is about getting computers to predict how physical things behave by learning from examples. One way is to represent a physical system as a network of points and connections—particles or mesh corners linked by their neighbors—and train a program to pass information along those links to predict what happens next, then run that prediction many steps ahead.

YouTube source · Talk page

Core Problem

Learning programs that predict what physics does can be fast, but they often fail when you try them on systems larger or shaped differently than what they saw during training. Physical simulations come in many forms: loose particles, triangular meshes, brick-shaped meshes, cloth that bends. An architecture that can handle all of these, including systems the program has never seen before, is rare and hard to build.

First-Principles Model

You can describe a physical system as a network: each point (particle or mesh corner) is a node, lines between neighbors are edges, and numbers attached to each node and edge hold the actual physics (position, velocity, force). A message-passing program reads those edges and nodes, updates each edge based on what its two endpoints say to each other, and updates each node based on messages from all its connected edges. After enough rounds of this talking-to-neighbors, you decode the numbers back into the next step of the simulation. Run this prediction step over and over to see how the system evolves.

Key Claims

  • A single architecture can learn to simulate particles, triangular meshes, solid meshes, and deformable cloth—just by changing which nodes and edges the network uses.
  • You train it to predict one step ahead, then roll that prediction forward many times to see the full trajectory.
  • Passing messages between connected nodes mirrors how physics itself works: each piece only directly affects its immediate neighbors.
  • The calculation gives the same answer no matter how you order or relabel the nodes and edges—the only thing that matters is who is connected to whom.
  • Because it learns relative positions and local interactions, it can extrapolate to bigger domains and different object placements than it saw during training.
  • A network-based representation generalizes better than treating space as a fixed grid (like photographs) when the system has an irregular or changing shape.

Worked Example

A cylindrical wake flow around a cylinder with 513 snapshots spanning 0–2 seconds is learned via graph neural networks. The full finite element model requires 1100 large linear solves on a 160k-unknown grid; the reduced model needs only 180 solves to build a 360-dimensional basis, yielding 4x cost reduction. Pressure field reconstruction shows less than 1 percent error in the domain interior, with graceful degradation outside training bounds. For a 2D water particle system trained on 128×128 pixels, generalizing to a much larger scene with continuous inflow generates vortex dynamics never seen during training—demonstrating mesh-independent, scene-agnostic learning.

One Level Deeper

Graph neural networks encode a physical system as nodes (particles/mesh vertices), edges (interactions), and global features (parameters). Message passing updates each edge by concatenating source/target node features and applying a shared MLP to compute forces/interactions. Node aggregation sums incoming messages (superposition principle) and updates each node using another MLP. Encoder maps raw state to graph, processor runs message-passing layers, decoder extracts accelerations or field updates. Inductive bias from encoding relative distances in edges grants translational equivariance; local neighborhoods reduce receptive field complexity; permutation-equivariance lets the same weights apply to any subset of particles.

Failure Boundary

Graph networks struggle with long-range dependencies or global coherence—information needs multiple message-passing steps to propagate. Scaling to very large particle counts (millions) becomes memory-prohibitive. Turbulent regimes with Reynolds numbers >1000 remain untested; high-frequency instabilities violate the smooth-dynamics assumption. Models trained on single Reynolds/material parameter may fail catastrophically outside that regime. Boundary conditions and contact dynamics (particle overlaps) require careful initialization with training noise; without noise injection, models accumulate error into physically impossible states (interpenetration, divergence) that weren't observed during training.

Important Terms

Graph Network

A program that operates on points (called nodes), the connections between them (called edges), and optionally properties of the whole network. It updates these pieces by having each point talk to its neighbors.

Message Passing

A way of computing where each connection between two points learns something from both endpoints, and each point learns something from all its connections. Information flows back and forth across the network.

Encode-Process-Decode

A three-step pipeline: first, turn a physical state (positions, speeds, forces) into a network. Second, run many rounds of neighbor-to-neighbor message passing to update that network. Third, turn the updated network back into the next physical state.

Rollout

Taking a one-step prediction program and running it many times in a row to see how a system evolves over many steps—like a long simulation starting from an example the program has never seen.

Permutation Equivariance

The property that the prediction stays the same if you relabel or reorder the points and connections. What matters is who is connected to whom, not arbitrary names or numbering.

Connections Across The Series

  • This talk introduces a way to represent physics using network structure as an alternative to grids or mathematical bases—the network directly tracks which parts of the system touch each other.
  • It connects to work on operator learning because both learn reusable maps between physical states, but graph networks focus on the local connection structure that the physics already has built in.
  • It also connects to concerns about long-term stability raised in talks on fluids and turbulence: errors from one-step predictions pile up over many steps, so the program must handle that compounding.

Practical Caution

When you test a graph simulator, look at how well it stays stable when you run many prediction steps in a row—not just whether its first prediction is close. Also test it on systems with different shapes and sizes than it trained on. Passing messages between neighbors helps the program generalize, but it does not by itself ensure that the physics rules are respected (like that energy doesn't vanish) or that the simulation stays stable as you run it forward in time.

Takeaway

Physical systems are built on local interactions: particles push only their nearby neighbors, heat spreads only to touching surfaces, forces act between connected mesh corners. Graph networks exploit this by learning to calculate these local, pairwise interactions using the same network structure that the physics already uses.
