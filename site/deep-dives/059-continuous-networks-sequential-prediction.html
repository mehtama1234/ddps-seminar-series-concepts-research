Talk 59 · University of Pittsburgh

Ben Erichson: Continuous Networks For Sequential Predictions

This whole series is about getting computers to predict how physical things behave by learning from data instead of using only hand-written equations. This talk focuses on time-series prediction—guessing what happens next in a sequence of measurements over time—by treating a learning program's prediction engine as if it were a rule describing how a system changes moment by moment. The talk shows how using better time-stepping methods (borrowed from centuries of mathematical tradition for simulating physical systems) and adding randomness to the learning process can make long-horizon predictions more reliable and accurate.

YouTube source · Talk page

Core Problem

Predicting sequences matters when computers are used to help with real physical science: modeling how air flows around objects, predicting climate shifts, simulating how fluids move. Standard learning programs designed for sequences can jitter wildly if the input wiggles even slightly, and they often miss the continuous, smooth way that real physical systems actually change—jumping from moment to moment in crude steps rather than capturing the smooth flow underneath.

First-Principles Model

Imagine a learning program that predicts the next value in a time series. Internally, it updates some hidden state one time step at a time. This is a discretized dynamical system: you start with initial conditions (the values right now), then a rule tells you how to jump to the next state, and you repeat. Now, classical math has spent centuries perfecting ways to take a smooth rule describing continuous change and chop it into discrete time steps reliably. The simplest approach—forward Euler—uses the slope right now to predict the next step, like extrapolating a straight line. Better methods, like explicit midpoint, peek at the slope in the middle of the time step to steer more accurately. You can also add random jitter into the evolution rule (stochastic differential equations) to make the system more robust. Multiscale methods recognize that some changes happen fast (like vibrations) and others slow (like drift), so you can represent them separately and still track the whole picture.

Key Claims

  • Time-series learning programs can be understood by viewing them as rules describing how a system evolves, just like the continuous equations scientists write.
  • Off-the-shelf deep learning programs may fail in real science because they can wobble wildly when inputs shift slightly, making them unreliable for safety-critical predictions.
  • Learning programs built on continuous-time thinking can be steadier and more accurate than the simpler building blocks usually used.
  • Time-stepping methods from classical mathematics—refined over centuries for solving equations—can be ported into learning architectures to improve predictions.
  • Using the midpoint of a time step to evaluate the rate of change, instead of just the current point, can be significantly more accurate without extra cost.
  • Adding randomness into the evolution rule (like physics equations with random forcing) and separating fast and slow dynamics both help models predict far into the future without drifting.

Worked Example

RNN on 1000-dimensional synthetic dynamical system, 200-step sequences. Traditional RNN (GRU, 256 units): ~15 min training, 200ms inference per sequence. Neural ODE continuous network: 64-dim hidden state, RK45 solver ~90s training, 8ms inference (25x faster per-step). MNIST sequence classification: pixel-by-pixel input, 28×28=784 steps, traditional RNN ~80% accuracy, continuous ODE network ~92% (gradient flow through adaptive timesteps captures long-range dependencies). Real data: EEG signals (200Hz sample rate, model predicts 1-5s ahead), continuous gives 15% lower MSE vs fixed-step RNN.

One Level Deeper

Neural ODE models hidden state evolution z(t) via ODE: dz/dt = f_θ(z(t),t). Forward pass: solve ODE from t_0 to t_1 using adaptive solver (Runge-Kutta 4/5). Adjoint method computes gradients by solving backward ODE: dλ/dt = -λ^T ∂f/∂z (no backprop through solver, memory O(1) vs O(N_steps)). Continuous-time loss L integrates residuals: L = ∫ ℓ(z(t), y(t)) dt. Advantages: variable-length sequences (no padding), adaptive computation (solver step-size = network attention), irregular sampling (inherit ODE continuity). Continuous recurrent networks parameterize latent dynamics as neural network; adjoint method backpropagates through ODE solution operator A(t) ≈ e^(tJ) where J is Jacobian of f.

Failure Boundary

Stiff ODEs (eigen spectrum spanning 10+ orders): adaptive solver requires tiny steps, nullifying speed advantage; total runtime 3-5x slower than fixed RNN. Chaotic attractors with positive Lyapunov exponent: gradient estimates via adjoint method unreliable beyond ~20 steps (exponential sensitivity). Irregular time grids (gaps >10× median step): ODE solver fails or requires global time interpolation, memory jumps to O(N). Very long sequences (>10K steps): adjoint backprop accumulates numerical error; Lipschitz constant of f_θ must stay <1 to prevent gradient explosion (requires careful initialization/regularization). Non-smoothness in data (jumps, delta-functions): ODE model unable to represent discontinuities.

Important Terms

Continuous-Time Recurrent Network

A learning program for sequences built on an underlying smooth rule describing how a system evolves, before that smooth rule is chopped into discrete time steps for a computer to execute.

Forward Euler

The simplest way to chop a smooth rule into time steps: draw a straight line from the current state using the current rate of change, and step to where it lands.

Explicit Midpoint

A better way to chop a smooth rule into time steps: evaluate the rate of change at the midpoint of the time step, not just at the start, to steer more accurately.

Stochastic Differential Equation

A rule describing how a system changes that includes random jitter or noise in addition to deterministic (always-the-same) forces; think of a system blown by random gusts as well as predictable forces.

Multiscale ODE

A rule describing continuous change where some parts evolve quickly (like a fast vibration) and others slowly (like a gradual drift), and you track them separately so neither one gets lost.

Connections Across The Series

  • This talk deepens the thread that neural network design—how you wire the architecture—is really applied mathematics: numerical stability and accuracy are not afterthoughts but core choices.
  • It pairs with earlier talks on physics-informed learning and neural differential equations, all stepping toward the same insight: teach machines physics by letting them inherit the best mathematical tools that scientists have built.
  • It offers a grounded alternative to designing learning models purely by trying things and seeing what works, instead rooting design in numerical methods that come with theoretical guarantees.

Practical Caution

A learning program's internal time step is not a dial you can twiddle carelessly. Changing the time-step size, swapping one stepping method for another, or adding noise changes whether the program stays stable when it runs for a long time. Before using any of these models in real science, you need to check numerically that they do not blow up, oscillate crazily, or drift away from the true answer.

Takeaway

Sequence models are numerical dynamical systems at their core. Better scientific designs come from treating them as such: use stable, accurate time-stepping methods (the ones that engineers have already refined), and think carefully about how fast and slow changes are both captured.
