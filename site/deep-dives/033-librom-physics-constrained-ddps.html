Talk 33 · Lawrence Livermore National Laboratory

Youngsoo Choi: libROM For Physics-Constrained Data-Driven Physical Simulations

This series chases one goal: getting computers to predict how physical things behave by learning from data instead of only writing down the hand-built rules that engineers have always used. One way to do this is to build a smaller, faster stand-in for a big, slow simulator—a reduced model that keeps some of the original math constraints baked in so it stays close to reality. This talk is about libROM, a working software toolkit that handles all the messy details: finding the hidden patterns in your data, speeding up calculations for tricky nonlinear systems, and tying pieces together so you can actually use reduced models in real simulations.

YouTube source · Talk page

Core Problem

Getting a computer to predict how air rushes over a wing, how heat spreads through metal, or how water sloshes is slow and costly if you start from scratch each time. You could train a learning program (a system with millions of dials the computer tunes by trial and error until its answers look right) on examples and skip the hand-built math—but that often fails because the program has no clue about the physics laws and breaks them. Or you could bake those laws directly into the training as hard rules and make the program respect them—but then you need working code, standard recipes, and ways to check that your result is trustworthy. LibROM steps in to give you that machinery.

First-Principles Model

The core idea: you have a full, detailed simulator that works but is too slow for repeated use. You gather a bunch of example runs from that simulator and look for hidden patterns—the handful of directions in the data that capture most of what's happening. You project all your data onto those directions, which shrinks the problem to a handful of numbers instead of millions. You build a small rule (a smaller version of the original) that evolves those few numbers over time. Finally, you unshrink the result back to the full size so a human can read it. For tricky nonlinear systems (where the rule isn't a simple straight line), this speedup breaks unless you're smart about which parts of the rule you actually calculate each step—that's called hyper-reduction, and it samples only the expensive parts that matter most instead of computing everything. LibROM bundles all these ingredients into one toolkit so you don't rebuild it yourself every time.

Key Claims

  • Physicists and engineers have always mixed real data with their written rules—think of tuning a weather model against measurements or calibrating an engine to match tests.
  • A learning program trained only on examples ignores the physics and often breaks in new situations; a program that also learns from the governing equations stays honest.
  • LibROM includes several recipes for finding hidden patterns in data—some that process all data at once, some that update as new data come in, and some that are fast but randomized.
  • When a system has tangled, nonlinear behavior, you must skip most of the expensive calculations each step, keeping only the few that change the answer—libROM does this.
  • The toolkit ships with ready-to-run examples: heat spreading through a rod, diffusion that eats itself, and fluid sloshing in a box.
  • For long simulations where material gets pushed far from its start, libROM can split time into windows or build a curved reduced model instead of a flat one.

Worked Example

A shaped charge penetration simulation takes 7.4 days per full-order solve. Using POD-based projection onto 20 basis modes reduces a 160,000-dimensional system to 20 ODEs. With hyper-reduction via DEIM sampling only 360 quadrature points instead of all 160k, speedup reaches 14.6–87.8× across Lagrangian hydrodynamics test cases while maintaining <0.1 percent relative error. For a Rayleigh–Taylor instability problem, speedup improves as problem size grows—from 10× on a smaller grid to 100×+ on fine meshes—because compressibility of the solution manifold outpaces dimensional growth.

One Level Deeper

Projection-based ROM approximates state as u ≈ V c where V contains POD modes and c are time-dependent coefficients. Galerkin projection onto V^T of the residual R(u) = 0 yields reduced system M c-dot + K c + Q(c) = 0, where M = V^T E V, K = V^T A V, and Q is the reduced nonlinear tensor. Hyper-reduction (DEIM) selects r << n sample indices via greedy algorithm, replacing Q(c) with Z Q-bar(Z^T c) where Z samples only the important modes. The sampling matrix enforces that nonlinear residuals vanish at selected DOFs, balancing accuracy against cost. Regularization tuning (SVD truncation, Tikhonov) handles ill-conditioning from near-collinear basis vectors.

Failure Boundary

ROM fails when the dominant modes don't span the solution manifold—happens in transport-dominated (high-Re) flows where sharp fronts move unpredictably. Linear projection cannot capture moving localized features; mode alignment requires training data spanning the full parameter space. For parametric problems, basis constructed at one parameter may be inaccurate at distant points; greedy parameter sampling helps but is expensive. Offline cost (computing POD, assembling M/K/Q, DEIM selection) becomes prohibitive for very high-dimensional systems (>10M DOFs). Nonlinear model order reduction via manifold learning or autoencoders adds further computational overhead and loses physical interpretability.

Important Terms

libROM

A working toolkit from Lawrence Livermore National Lab that builds smaller, faster stand-ins for physics simulators by blending data patterns with the governing equations.

Physics-Constrained ROM

A small, fast stand-in for a physics simulator that uses both real examples and the actual governing equations to stay accurate.

Incremental SVD

A step-by-step recipe that finds hidden patterns in data as new examples arrive, updating the answer each time without redoing all the math from scratch.

DEIM

Discrete Empirical Interpolation Method—a trick to skip most of the expensive calculations in a small model by computing only the tangled nonlinear parts that actually matter.

Component-Wise ROM

A small model made from several even-smaller pieces that each describe one part of the system, wired together to work as a whole.

Connections Across The Series

  • Earlier talks in this series showed what's possible in theory—finding hidden patterns, speeding up tangled nonlinear models, and building models from linked pieces. This talk shows how to actually do it with real code you can run.
  • It connects to talks on finding hidden patterns in data, hyper-reduction for speed, and assembling linked systems by showing them as reusable ingredients in libROM.
  • It also completes the arc of the whole series: concepts alone don't matter—you need a toolkit you can hand to someone and say, 'Use this to build a smaller, faster, trustworthy simulator.'

Practical Caution

A toolkit makes the workflow smoother, but it can't think for you. You still have to decide: which hidden patterns to use, which sampling points to take, what physics to bake in, and how to verify your answer is close to the full simulator. The software just does the bookkeeping—the judgment calls are yours.

Takeaway

Building computers that learn to predict physics requires two things: working code and human insight. LibROM is the engineering layer that turns the math ideas into something you can actually repeat, share, and trust.
