Talk 111 · Weierstrass Institute

Francesco Romor: Intrusive Model Order Reduction Using Neural Network Approximants

This whole series is about getting computers to predict physical behavior by learning from examples instead of only hand-written math. One popular shortcut is to throw away unnecessary details and keep only the most important numbers—a process called model reduction. This talk shows one way to do that: use a learning program (a system with millions of little dials tuned by trial and error) to spot the smooth curved surface where all the solutions live, then run the actual physics equations on that compressed shape during prediction, so you get the speed of learning plus the trust of keeping the real physics visible.

YouTube source · Talk page

Core Problem

When you want to predict how something physical behaves—say, how heat spreads through a complex metal part—you can either write down all the rules (a rule that says how something changes from moment to moment or place to place) or let a computer learn from examples. A fast way to do both is to compress the problem: find a much smaller set of numbers that hold the key information. The old standard way does this with flat mathematical sheets (picking just a few main directions where solutions move), but this fails when the actual solutions wiggle around in a curved shape that flat sheets can't capture well. Learning programs are good at spotting curved shapes, but most of them forget the physics rules entirely once they've learned, turning into pure guesses with no connection to the real equations.

First-Principles Model

This method keeps the actual physics equations running during prediction instead of abandoning them. It uses a learning program—specifically one that compresses data by squeezing it through a narrow middle layer, then rebuilds it on the other side—to find the curved surface where answers actually live. This squeezed shape has far fewer numbers than the original problem, so the physics equations run much faster on it. Then techniques that avoid computing expensive parts (only checking whether the physics rules hold at a few key spots rather than everywhere) make the cost even lower. The payoff is that you get both the speed of a compressed model and the visibility and trustworthiness of keeping the real equations in the loop.

Key Claims

  • When solutions form a curved shape that doesn't lie flat, traditional compression methods (keeping only main directions) can't capture it well without keeping too many numbers.
  • Learning programs can spot curved surfaces accurately in data.
  • Most current learning-based reduced models toss away the equations after training and become pure guesses.
  • A model that stays intrusive—keeps the equations running during prediction—gives you both speed and visible physics.
  • A learning program that compresses by squeezing through a narrow middle layer can reduce the number of important numbers while keeping curved surfaces.
  • Techniques that evaluate physics rules at only a few key spots (instead of everywhere) make the compressed model fast enough to use.

Worked Example

Heat transfer on unstructured mesh (32,000-200,000 cells): ROM with 300 modes computed via randomized SVD (RSVD) in <5 seconds. Latency: 74 ms per inference vs 10-100 seconds for full CFD solve. Speedup: 135-1350x depending on problem complexity. Adaptive magic points: instead of projecting residual onto all basis vectors (cost O(n_dof·n_modes²)), select 150-200 critical sample points where residual varies most (QR-pivoting on Jacobian at these points). This reduces projection cost from O(n) to O(m) where m = magic point count << n. Tested on Burgers equation (2D domain, 1000 snapshots): ROM error stays <1% for 50 timesteps forward prediction, then grows linearly (~0.1% per additional step). For 500-step prediction, error reaches ~5%.

One Level Deeper

Intrusive ROM: given full discretization du/dt = F(u), project to reduced basis V ∈ R^{n×k}: d(V^T u)/dt = V^T F(V·(V^T u)). Cost: evaluating F still requires n FOM operations, but ROM state (V^T u) is only k-dimensional. Magic points reduce this: select m collocation points where F evaluated, approximate full projection by interpolating (Empirical Interpolation Method, EIM). Loss: ||V^T F - W·diag(f_m)||_F where W ∈ R^{k×m} weights the interpolated values and f_m are FOM evaluations at magic points only. Basis update via POD: SVD(snapshots matrix X) = U·Σ·V^T, keep top k singular vectors as V. RSVD uses randomized projections to compute this in O(n·k·log n) time.

Failure Boundary

Basis decay: POD spectrum (singular values Σ) saturates for chaotic flows; many modes contribute equally, defeating compression. Magic point placement is fixed during training; if dynamics shift into unexplored regions, interpolation error explodes. Long-time integration: nonlinear ROMs drift away from attractor; residual grows quadratically in prediction time T. Parameter dependence: single ROM trained on one set of boundary conditions/Reynolds number fails on new parameters; must recompute basis for each case. Stiffness in ROM: temporal dynamics in reduced space can become more stiff than full model, requiring tiny timesteps despite dimensional reduction.

Important Terms

Intrusive Model Reduction

Compressing a physical problem while keeping the actual governing equations running during prediction, so you stay connected to the real rules.

Kolmogorov n-Width

A number that measures how many main directions (like finding just the 3 most important compass directions out of infinite directions) you need to capture a curved surface well; if it decays slowly, you need many directions.

Solution Manifold

The smooth curved surface or shape traced out by all the different answers as you change the input numbers or physical parameters.

Autoencoder

A learning program that compresses data by squeezing it through a narrow middle layer with fewer numbers, then rebuilds it back to full size; the narrow middle layer captures the essential patterns.

Hyper-Reduction

Techniques that speed up an equation solver by checking whether the physics rules hold true at only a few selected spots instead of everywhere, cutting computation time dramatically.

Connections Across The Series

  • This talk brings together three big ideas from the seminar: how to compress high-dimensional problems, how learning programs can spot curved shapes in data, and how to keep equations visible while adding learning.
  • It contrasts with talks about pure data-driven learning by explaining why keeping the original physics equations matters for trust and speed.
  • It also relates to talks about finding the main directions in data by showing that curved surfaces—not just flat sheets—can hold the key to fast, accurate predictions.

Practical Caution

This approach requires that you have access to the actual governing equations and the numerical program that solves them, not just examples of past predictions. That's a strength—you can see and verify the physics—but a weakness when you only have a simulator that spits out answers without letting you look inside. It's harder to set up than methods that just learn from data alone, and when you move it to a new computer or new problem, it requires careful handling of the equations themselves.

Takeaway

Using a learning program to spot curved shapes works best when you treat it as a helper alongside the physics, not as a replacement for it. The equations stay, the learning program just compresses the search space.
