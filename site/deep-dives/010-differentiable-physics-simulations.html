Talk 10 · Technical University of Munich

Nils Thuerey: Differentiable Physics Simulations For Deep Learning

This whole series is about getting computers to predict how physical things behave by learning from examples instead of only hand-built math. This talk shows how to connect simulators and learning by making the simulator compute gradients — think of them as tiny signals showing which direction to nudge inputs to get closer to a desired physical outcome — so those signals can guide learning, answer puzzles about what caused an observation, and improve how we control things.

YouTube source · Talk page

Core Problem

Simulators are programs that step through physical situations (air flowing, heat spreading, water sloshing) moment by moment to predict what happens next. Most people use simulators just to create training data: run it many times with different inputs and collect results. But this misses something important. Many real problems ask: if I change an input, a parameter, or a control action, how would the physical result change? To answer that question precisely, you need gradients — numerical signals that flow backward through the simulator showing how much each earlier step contributed to the final answer.

First-Principles Model

A simulator takes a starting state, parameters, or control actions and predicts what the physics will do next. Most simulators can only run forward: plug in numbers, get answers. A differentiable simulator also computes gradients — which inputs and parameters mattered most to the final result. This opens up new possibilities. You can reverse the question: start from an outcome you want and work backward to find what starting state or control action would produce it (this is called an inverse problem). You can reduce errors built into the numerical method itself by training a learning program to spot and fix them. You can train learning programs inside the physics loop by having gradients flow from the simulator back to the program's dials. The simulator stops being just a tool to generate data and becomes a step in the optimization process itself.

Key Claims

  • Physics models and the numerical methods used to solve them have real value and should be kept when possible, with learning handling measurement noise, gaps in observations, and effects we don't know about.
  • Running a simulator forward shows what will happen; asking inverse problems means finding what starting conditions or actions would create a desired outcome.
  • Learning from data made by simulators is helpful but loosely connected to the actual physics.
  • Telling a learning program the physics rules in its loss function (a score measuring how wrong its answers are) creates a tighter link, but building the simulator itself into the learning process creates the closest connection.
  • What matters most is the gradient showing how the simulation's final result would change if you tweaked the starting conditions or control action.
  • Solvers (programs that compute physical predictions) that can compute gradients can be used inside the training loop for learning, control, and fixing errors in approximate numerical methods.

Worked Example

2D cylinder wake flow with obstacle: domain 128x64, 10-32 timesteps, Re ~ 100-200. Solver-in-loop approach reduces mean absolute error from ~0.14 (naive supervised) to ~0.013 (with neural correction). 3D flow requires ~900s CPU reference simulation vs 13-14s hybrid (source + network correction) = 60-70x speedup. Network trains under 100 epochs to stabilize double integrator control task.

Smoke plume fire exit control: 2D domain 128 sq, 16 timesteps, 5000+ continuous control parameters. Solver-in-loop enforces differentiability through entire unroll, enabling gradient-based optimization where RL fails. Achieves sub-optimal but satisfactory control solutions vs reinforcement learning instability.

One Level Deeper

PDE-aware solver loops integrate automatic differentiation through numerical schemes. Forward pass: solve PDE residual |∂u/∂t - N[u]|² using neural network correction C[u; θ] added to coarse solution. Backward pass: compute adjoint of entire solver stack to backprop sensitivity ∇L/∇θ. Key: replace naive supervised l2 loss (reference data only) with solver-in-loop loss that sees denoised but evolving system states. Adjoint computation uses same discretization (e.g., Runge-Kutta 4) for both forward and backward to preserve accuracy.

Failure Boundary

Method struggles with chaotic systems where small state perturbations diverge exponentially; adjoint instability can emerge with long unrolled horizons (100+ steps). Shifting distribution problem occurs when network sees only source simulator during supervised training but must generalize to hybrid dynamics during deployment. For 3D flows at high fidelity, memory footprint for storing full trajectory during backpropagation becomes prohibitive; wall-clock cost of reference solver generation can dominate if problem requires many training episodes.

Important Terms

Differentiable Simulator

A program that runs physics forward and also computes gradients showing how much each input, state, control signal, or parameter affected the final answer.

Solver-In-The-Loop

A learning system where a program that predicts physics runs as part of training and passes back gradient signals to guide how the learning program tunes its dials.

Adjoint

A method for efficiently calculating what change in an earlier step would have been needed to cause a small change at the end — the reverse direction of a forward simulation.

Inverse Problem

A puzzle where you start with an outcome (measured or desired) and work backward to find the hidden causes, parameters, or actions that would produce it.

Numerical Error Correction

Training a learning program to spot and fix errors that come from using coarse grids, simple mathematical approximations, or fast but imprecise solvers.

Connections Across The Series

  • This is the differentiable-simulation foundation for the seminar series and extends earlier talks about adding physics to learning by moving the solver into the learning process itself.
  • It connects to controlling systems, designing objects better, simulating fluids, and upcoming talks about machine learning applied to science.
  • It also bridges adjoint methods from classical scientific computing to today's automatic differentiation tools (programs that compute gradients automatically).

Practical Caution

Gradients are useful only if they truly reflect what happens in the real physics and if calculating them stays fast. Physics code that mixes many different types of physics, makes predictions far into the future, has sudden jumps (like objects colliding), or uses math that grows unstable can make this approach impractical. The nice theory works best when the simulator is stable and relatively simple.

Takeaway

Gradients let you optimize through simulation instead of just using it as a data source. This is why differentiable physics matters for inverse problems (finding what caused an observation), control (making something behave as you want), and machine learning applied to science.
