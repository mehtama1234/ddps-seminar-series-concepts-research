Talk 113 · Georgia Tech

Elizabeth Qian: Multi-Fidelity Linear Regression for Scientific Machine Learning from Scarce Data

This whole series is about getting computers to predict how physical things behave by learning from examples instead of hand-written math. When you have only a tiny amount of trustworthy data, this talk shows how to add cheaper, cruder guesses to the mix: the computer learns from the cheap wrong guesses to narrow down its wild swings, then uses the rare expensive data to fix the direction it's off in.

YouTube source · Talk page

Core Problem

To predict how a wing cuts through air or heat spreads through metal, scientists build stand-in programs that run fast (instead of watching it really happen or running slow step-by-step math). These stand-ins need lots of examples to learn from. Collecting those examples costs real money and time. When you train a model on just a few examples, it memorizes each one instead of spotting the true pattern underneath. Imagine a student who only sees three word problems and tries to guess the rule: if it gets lucky, great, but usually it invents a weird pattern that only fits those three. That breaks when the student tries a new problem.

First-Principles Model

Multi-fidelity learning accepts a real tradeoff: the best simulations give you accurate answers, but you can afford to run only a handful; cheap, rough approximations are fast to generate, but they're biased (always off in some direction). Stack them this way: flood your model with lots of cheap, rough data so it stops making wild guesses all over the place, then use the few precious expensive runs to correct the direction the cheap data pulled it. For linear models (where you fit a line through your points), you can see exactly how these two sources combine when you hardly have any good data at all.

Key Claims

  • When the model sees only a few real examples, it starts memorizing those examples instead of learning the true rule underneath.
  • Lower-quality data can be useful even when it's consistently wrong.
  • Linear regression with multiple data sources gives a clear way to understand this larger idea.
  • Real science problems always have data at different quality levels and different costs naturally built in.
  • The goal is to make predictions work when you run out of expensive, trustworthy data.
  • This method recasts the small-data puzzle as balancing two things: how much the predictions wobble side to side, versus how much they tilt in one direction, weighed by what each type of data costs.

Worked Example

The 1D warm-up fits a quartic (constant plus first-through-fourth-order features) to an exponential high-fidelity function, with a shifted exponential as the cheap low-fidelity model: the low-fidelity model costs 1/1000 of the high-fidelity one and correlates about 97%. Fixing a data budget, high-fidelity-only training spends the whole budget on F1 samples, while the multifidelity method uses the MFMC allocation formula -- for a budget of 10 it puts about 80% on high-fidelity and the rest on many cheap low-fidelity samples. Plotting realizations, the high-fidelity-only quartic fits (even with 100 samples) scatter widely around the true best-fit, whereas the multifidelity fits cluster tightly near it: much lower variance, hence more robust.

The PDE example is a 2D convection-diffusion-reaction (one-step chemistry) problem with 5 input parameters (Arrhenius A, activation energy, inflow temperature, wall temperature, fuel-oxidizer ratio), predicting the steady-state maximum chamber temperature with a quartic model (~25 features). High-fidelity data is a 2D finite-difference solve costing 1.9 seconds; low-fidelity is a POD-DEIM reduced model costing about 6/1000 of a second, and the two models correlate about 95%. With exact statistics the optimal matrix gain A* does best, but when statistics must be estimated the A* becomes wildly bad (its condition blows up to ~10^20), so the recommended practical choice is the optimal scalar coefficient alpha*, which consistently gives lower prediction variance and lower generalization error than high-fidelity-only training of equal cost.

The gains are largest in the scarce-data (low-budget) regime, which is the whole point: narrower error bands and lower mean error exactly where high-fidelity data is too expensive to collect.

One Level Deeper

Control variates reduce estimator variance: to estimate a mean, form mu_hat_CV = (sample mean of F1) + alpha * ( mu_W - sample mean of W ), where W is a correlated cheap surrogate. It stays unbiased because E[W] cancels the correction in expectation, and the variance-minimizing gain is alpha* = Cov(F1, W)/Var(W), giving Var(mu_hat_CV) = Var(mu_hat_MC) * (1 - rho^2). So the higher the correlation rho between high and low fidelity, the more variance you kill. The multifidelity variant (MFMC) replaces the exact mu_W with a many-sample low-fidelity estimate and allocates m >> n samples to the cheap model, with n high-fidelity samples nested inside.

For linear regression the target is beta* = C_xx^{-1} C_xy, where C_xx = E[x x^T] (feature covariance) and C_xy = E[x y] (feature-output covariance). The expensive part is C_xy because every y needs an expensive model run, while C_xx depends only on features and can be treated as known from abundant free inputs -- so they hold C_xx exact and apply the control-variate variance reduction to the C_xy estimate. Crucially they use the modified (C_xx-exact) estimator because inverting a noisy sample C_xx would bias beta, and unbiasedness is what they need. The vector control-variate estimator is C_xy_MF = (m-sample low-fi term) - A (n-sample correction), where the scalar alpha is now a matrix gain A; the trace-of-covariance-minimizing choice is A* = Gamma_12 Gamma_22^{-1} (cross-covariance of the feature-weighted functions over the low-fi auto-covariance), the matrix analogue of Cov/Var.

Because beta_MF is linear in C_xy_MF and C_xy_MF is unbiased, beta_MF and the model predictions are provably unbiased regardless of the low-fidelity data quality -- lower variance in C_xy propagates to lower variance in beta and in predictions.

Failure Boundary

The method needs sufficiently high model correlation and a high enough cost ratio; variance reduction scales like (1 - rho^2), so weakly correlated models buy little unless they are extremely cheap (in Monte-Carlo settings the speaker used rho as low as ~38% only because the cost ratio was ~10^6). The estimated-statistics problem is the sharp practical edge: the theoretically optimal matrix gain A* depends on covariance matrices that need many pilot samples, and with too few pilots A* is catastrophically bad (condition ~10^20 in the PDE case), so you must fall back to a scalar coefficient. Unbiasedness survives bad statistics, but the optimality of the variance reduction does not.

Scope limits: it is developed for shared-input, scalar-output linear regression. Different input domains for the two models break the shared-input assumption and need more research; vector outputs and nonlinear regression (e.g. neural networks) are open, and for a model whose parameters enter nonlinearly the clean unbiased control-variate structure no longer applies directly. It also assumes the low-fidelity data is simply given; the cost of building the low-fidelity model (e.g. training the POD surrogate) is not counted.

Important Terms

Multi-Fidelity Learning

Training a model using data sources that differ in cost and accuracy — some cheap but wrong, others expensive but right — to get better predictions when data is scarce.

High-Fidelity Data

Accurate results from running a full realistic simulation or a real experiment; costs money and time to collect.

Low-Fidelity Data

Cheaper, quicker results from using a coarse, simplified model or rough educated guess instead of the real thing.

Linear Regression

A simple model that assumes what you're predicting is a straight line plotted against the input measurements.

Scarce Data

Having so few reliable training examples that the model's guess bounces all over the place; it can't tell real patterns from random noise in what it saw.

Connections Across The Series

  • This talk weaves together measuring confidence (how sure is the prediction?), picking which experiment to run next smartly, building fast stand-in models, and squeezing learning from barely any data.
  • It extends earlier talks on neural operators and model reduction by showing that the cost and accuracy of data sources both matter for what a model can learn.
  • It speaks to how to pick good training examples when running a full simulation is expensive.

Practical Caution

The cheap data shrinks the wild swings but brings its own steady tilt. Whether mixing different data sources actually helps depends on one thing: is the relationship between cheap guesses and expensive truth the same everywhere you want to make predictions? If the cheap model works one way in some regions and different in others, stacking them can backfire.

Takeaway

When training data is scarce, the model learns more by pulling hints from cheap, easy sources while staying honest about which data actually deserve trust.
